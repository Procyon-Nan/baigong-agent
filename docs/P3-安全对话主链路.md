## 1. 阶段目标

P3 在 P2 的统一身份与授权上下文上交付第一条可实际运行的安全对话链路：

1. 管理员可以在管理页面配置一个 OpenAI Chat Completions 兼容模型。
2. 本地普通用户、管理员和嵌入用户均可与主 Agent 进行纯文本、多轮、流式对话。
3. 所有创建、继续、取消和普通用户流读取均经过 BFF，并执行身份、租户、所有权和并发校验。
4. 普通用户只接收应用定义的安全事件；管理员可通过短期令牌直连 eve 专用入口读取原始事件。
5. 会话句柄、当前运行状态、请求幂等和单轮模型配置快照在 PostgreSQL 中持久化，不依赖进程内存。
6. 交互式对话中的模型调用错误只结束当前一轮回复，不终止整个 eve 会话；管理员修复模型配置后，用户可以在原会话继续。

P3 与 P4 共同组成完整的可恢复对话能力。P3 负责安全运行所必需的控制面和实时链路，P4 再补充会话列表、完整历史、安全事件持久化、Token 汇总和审计索引。

## 2. 范围边界

### 2.1 P3 范围

- 单个 OpenAI Chat Completions 兼容提供商、单个模型和主 Agent 当前模型配置。
- 提供商凭据本地加密、配置写入/替换/删除和可选连通性测试。
- 主 Agent 纯文本会话的创建、继续、取消、状态查询和安全 NDJSON 流。
- PostgreSQL 会话控制记录、单轮交互记录、请求幂等、用户并发限制和模型配置版本快照。
- BFF 到 eve 的短期服务 JWT，以及管理员原始流短期 JWT。
- 普通用户显式允许列表事件投影和管理员原始事件流。
- 本地主页、嵌入页面和管理员执行详情视图。
- 受限 Markdown 渲染。
- eve 交互式会话错误恢复语义修改及对应依赖集成。

### 2.2 不在 P3 范围

- 多 Agent 选择、Agent 实例管理、模型分配矩阵和可编辑提示词。
- Tool、终端、文件读写、Skill、Connection、Sandbox 和 Subagent 能力。
- 文件或多模态输入、知识库检索和受控文件下载。
- 会话列表、搜索、归档操作、完整历史恢复和安全事件数据库副本。
- Token 汇总表、Tool/命令审计索引和 Subagent 父子关系。
- 消息编辑、分叉、重新生成、自动标题和消息队列。
- 按分钟请求限流、Token 预算、成本预算和管理员可配置并发限制。
- P9 的正式嵌入组件包、完整宿主接入文档和示例。

## 3. 已确认的产品规则

### 3.1 Agent 范围

- P3 只允许与代码注册的主 Agent 对话。
- 会话创建后绑定主 Agent，不允许在会话中切换 Agent。
- 客户端不能声明任意内部 Agent 标识；服务端将当前 P3 Agent 固定解析为主 Agent。
- P5 为固定主 Agent 启用 eve 原生单层 Subagent 和版本化 Tool/Skill 能力；P7 再扩展其他 Agent 实例及分配管理。

### 3.2 输入范围

- P3 只接受非空纯文本消息，不接受文件、URL 附件、Data URL、Base64 或任意客户端上下文对象。
- 每条消息最多 32,000 个 Unicode 字符，请求体最多 128 KiB。
- 只允许 `message` 和 `requestId`；未知字段失败关闭。
- 客户端不能提交消息角色、系统提示词、模型参数、内部用户、租户、Agent 配置或 eve 句柄。
- Markdown 只是显示格式，提交给 Agent 时仍是普通 `user` 文本，不能改变 Prompt 层级或授权。

### 3.3 单轮交互

本文件使用“单轮交互”表示 eve 的 `Turn`：用户发送一条消息，Agent 完成该消息触发的模型调用和后续处理，直到重新等待用户输入。

- 同一会话同一时间只允许一个活动的单轮交互，不自动排队。
- 会话处于创建、运行或取消中时再次提交消息，返回 `409 CONVERSATION_BUSY`。
- 不同会话可以并发运行。
- 每个用户跨全部主会话最多同时生成 3 个主 Agent 回复；第 4 个主 Agent 请求返回 `429 USER_CONCURRENCY_LIMIT`。
- Subagent 不计入主 Agent 的 3 个并发额度；Subagent 使用 P5 定义的独立并发语义。
- 本地用户、嵌入用户和管理员自己的普通聊天使用相同并发限制。
- 管理员查看原始流或取消他人任务不占用其个人生成额度。

### 3.4 新建与恢复

- 不创建空会话。用户发送第一条消息时才创建应用会话和 eve 会话。
- 点击“新对话”只清除当前前端选择，发送消息后才写入新记录。
- P3 支持已知 `conversationId` 的继续、取消、状态查询和游标重连。
- `conversationId` 是不可预测的应用资源标识，可以出现在本项目页面路径中，但不是授权凭据。
- P3 不提供会话列表和完整历史重建；P4 完成刷新后的权威历史恢复。
- 嵌入页面刷新后必须按 P2 重新取得票据；重新认证后仍需通过所有权校验才能恢复已知会话。

## 4. 最小模型配置闭环

### 4.1 P3 配置能力

P3 将完整模型管理的一条最小纵向链路从 P7 前置，以便真实对话可验收：

- 提供商显示名称。
- Base URL。
- 可选 API Key。
- 模型名称。
- 可选最大上下文窗口 Token 数。
- 当前配置状态和版本。

P3 每个租户只维护一个当前模型配置，且主 Agent 是唯一使用者。P7 在此数据和服务边界上扩展多提供商、多模型和 Agent 分配，不重新实现凭据加密或运行时解析。

### 4.2 Base URL

- 开发和生产均允许管理员配置 `http:` 或 `https:`，不强制 HTTPS，也不限制回环、内网或公网地址。
- HTTP 风险由配置该地址的管理员承担；页面可显示非阻断性提示，但不能阻止保存、测试或使用。
- URL 不允许用户名、密码、查询参数、Fragment 或 HTTP/HTTPS 以外的协议。
- 服务端不自动跟随跨 Origin 重定向。
- Base URL、API Key 和模型名称只来自当前租户的数据库配置。
- 任何环境都不读取环境变量中的模型提供商凭据。

### 4.3 可选 API Key

- API Key 允许为空；为空时不能发送 `Authorization` Header，也不能回退读取 `OPENAI_API_KEY` 等环境变量。
- 有值时仅在服务端按需解密，并以提供商要求的认证 Header 发送。
- 管理页面不回显明文，只允许替换或清除。
- API Key 不进入日志、审计元数据、Prompt、Sandbox、错误响应或测试快照。

### 4.4 最大上下文窗口

- 最大上下文窗口是可选正整数。
- 管理员填写后，作为模型配置版本的一部分传给 eve，并显示在对话界面。
- 未填写时仍允许使用模型，界面显示“未配置”，不得根据模型名称或 Token 用量猜测。
- 未知上下文窗口时，不启用依赖该值的自动压缩阈值判断；上下文超限由模型端返回错误。
- 若未来明确适配的提供商响应包含可靠上限，可同时展示“管理员配置值”和“提供商报告值”；运行时以前者为准。

### 4.5 保存与连通性测试

- 字段完整且格式合法的配置保存后立即成为主 Agent 当前配置，不要求测试成功。
- 连通性测试完全可选，不控制配置启用状态。
- 仅在管理员点击“测试”时发送一次真实 Chat Completions 请求。
- 固定测试提示词为：`你好，请问你是谁，来自何处？`
- 测试请求不设置模型输出 Token 上限。
- 页面展示完整模型文本输出、耗时和提供商返回的 Token 用量（若有）。
- 测试输出只即时返回，不创建业务会话，不写入对话历史或长期记忆。
- 测试失败只返回脱敏错误，不自动停用配置。
- 连通性测试单次请求总超时为 5 分钟。

### 4.6 对话模型超时

- 正常对话的每次模型调用总超时为 15 分钟。
- 一次回复未来可以包含多次模型调用或 Tool 执行，因此不对整次回复设置统一 15 分钟上限。
- 用户取消时立即通过同一 `AbortSignal` 停止当前模型请求。
- 超时错误遵循统一的最多 3 次尝试规则。
- 超时值在 P3 固定，P7/P10 后续再提供管理员运行限制。

## 5. 凭据加密与版本

### 5.1 加密

- 复用 `src/server/config/data-directory.ts` 中的数据目录和 `credential-encryption.key`，不建立第二套密钥目录。
- 使用 `AES-256-GCM`，每条密文使用独立的密码学随机 nonce 和认证标签。
- 加密关联数据至少绑定租户、模型配置版本、字段用途和密文格式版本，防止密文跨记录替换。
- `continuationToken` 使用同一主密钥但不同字段用途、nonce 和关联数据加密。
- JWT 使用独立的 `jwt-signing.key`，不得与 AES 主密钥混用。

### 5.2 不可变模型配置版本

- 每次修改 Base URL、API Key、模型名称或上下文窗口都创建新的递增版本，不覆盖旧版本。
- 租户只保存一个当前版本指针。
- 每次用户发送消息时锁定当前模型版本；正在生成的回复始终使用该版本。
- 管理员中途修改、停用或删除配置，只影响下一条新消息，不强制切换或中断已开始的回复。
- 同一会话的下一条消息使用届时最新的模型配置，而不是永久绑定创建会话时的版本。
- 旧版本加密凭据保留到不再被任何活动回复引用，以支持 durable 运行在进程重启后继续。
- 旧版本不再被活动回复引用后删除其加密凭据，只保留非敏感版本、模型和使用快照。
- 管理页面不提供旧凭据恢复或回显。

## 6. eve 前置兼容修改

### 6.1 当前冲突

安装的 eve `0.27.11` 会把认证错误、模型不存在、无效请求等模型调用错误分类为终止错误，并产生：

```text
step.failed -> turn.failed -> session.failed
```

`session.failed` 会终止 continuation token，管理员修复模型配置后也无法继续原会话。这不符合本项目确认的交互式对话语义。

### 6.2 目标语义

必须在 eve 源码中修改交互式对话模式的模型错误处理：

- 所有模型调用错误采用统一的最多 3 次尝试和退避规则。
- 不单独排除 API Key、模型不存在、参数错误或其他确定性错误。
- 3 次均失败后产生 `step.failed -> turn.failed -> session.waiting`。
- “可恢复”只表示会话可以接收下一条消息，不自动补跑失败回复。
- 用户下一次明确发送消息时，使用最新模型配置并保留原 eve 会话上下文。
- 取消不属于模型失败，不执行重试。
- 任务模式、定时任务和无人继续输入的 Subagent 保持原有终止语义。
- eve 工作流结构损坏、持久化失败、状态反序列化失败等无法保证状态完整性的异常仍产生 `session.failed`。

### 6.3 交付要求

- 在 `/mnt/e/dev/eve` 的实际源码中修改，不编辑 baigong-agent 的 `node_modules`。
- 增加覆盖认证失败、模型不存在、普通 `4xx`、限流、超时、`5xx`、连续 3 次失败及修复配置后原会话继续的测试。
- 更新 eve 公开文档和 changeset。
- baigong-agent 最终依赖包含该修复的确定发布版本或确定 Git 提交，不提交 `file:` 本地路径依赖。
- P3 未使用确定的已修复 eve 构建完成集成测试前，不得标记完成。

## 7. 主 Agent 运行时

### 7.1 OpenAI Chat Completions

- 项目直接依赖与当前 AI SDK 版本兼容的 OpenAI Provider 包，不导入 eve 的编译内部模块或间接依赖。
- 运行时显式选择 Chat Completions 模型接口，不使用 OpenAI Responses API。
- 模型名称按管理员填写值原样传给兼容端点，支持例如包含 `/` 或 `:` 的自定义名称。
- 自定义请求层必须显式处理可选 API Key、禁止跨 Origin 重定向、请求取消、超时和响应体安全边界。

### 7.2 动态模型解析

自定义 Base URL 和数据库凭据要求运行时创建 `LanguageModel`。eve 的动态模型约束决定持久化作用域只能保存可序列化模型标识，实时模型对象只能在模型步骤开始时返回。因此采用以下方案：

1. BFF 在接收消息时锁定 `modelConfigVersionId`，写入单轮交互记录。
2. BFF 服务 JWT 携带签名后的应用 `turnId` 和 `modelConfigVersionId`。
3. eve 将签名身份投影为当前会话调用方上下文。
4. `step.started` 动态解析器读取同一轮已锁定版本，从 PostgreSQL 读取并解密配置，创建 Chat Completions `LanguageModel`。
5. 同一轮的所有模型步骤始终解析同一个版本。
6. 下一条用户消息由 BFF 重新锁定届时当前版本。

动态解析失败时使用现有“模型未配置”失败模型，不回退到代码内置生产模型。

### 7.3 默认系统提示词

P3 使用版本控制下的最小系统提示词，只约束：

- 使用用户所用语言回答。
- 回答准确、简洁，不虚构能力、事实或检索结果。
- 无法确认时明确说明。
- 不声称已经具备尚未实现的知识库、文件、终端、Tool、Skill 或 Subagent 能力。

系统提示词不包含身份、租户、权限、Base URL、API Key 或其他运行时敏感信息，也不承担授权职责。P7 再实现可配置提示词和版本快照。

### 7.4 P3 临时禁用能力

eve 默认 Harness 可能自动提供内置 Tool。P3 必须使用 `disableTool()` 文件显式禁用：

- `bash`
- `read_file`
- `write_file`
- `glob`
- `grep`
- `web_fetch`
- `web_search`
- `todo`
- `ask_question`
- 根 Agent 自我委派 `agent`

P3 不声明 Sandbox、Skill、Connection 或 Subagent。P5 固定启用 eve 原生 `ask_question` 和根级 `agent`，按能力版本动态提供 `todo`、`web_fetch`、专用会话附件 Tool与数据库 Markdown Skill；eve 原生 `web_search` 继续禁用，未来由本项目实现独立搜索 Tool。`bash`、`read_file`、`write_file`、`glob` 和 `grep` 在当前 P1 至 P10 路线内持续禁用；未来重新启用终端、Sandbox 或通用文件能力必须经过独立设计和安全评审。

## 8. 最小控制面持久化

### 8.1 模型配置表

建议职责如下，最终表名遵循现有 Drizzle 命名规范：

| 数据职责 | 关键字段或约束 |
| --- | --- |
| 模型配置当前指针 | `tenant_id` 唯一、当前版本 ID、更新时间 |
| 模型配置版本 | 版本 ID、租户、递增版本、显示名称、Base URL、模型名称、可选上下文窗口、加密凭据、创建者和时间、凭据清理时间 |

模型配置版本不可原地修改。当前指针更新和新版本创建必须在同一事务中完成。

### 8.2 会话控制表

| 数据职责 | 关键字段或约束 |
| --- | --- |
| 应用会话 | `conversation_id`、`tenant_id`、不可变所有者、身份来源、固定主 Agent、eve `session_id`、加密 continuation token、状态、活动单轮 ID、最后观察到的原始游标、时间戳 |
| 单轮交互 | 应用 `turn_id`、会话、客户端 `request_id`、eve turn ID、锁定模型版本、状态、开始/结束时间、公开错误码 |

P3 不保存完整消息正文或完整安全事件历史。P4 在同一会话和单轮记录上增加事件、消息、Token 和审计索引，不建立平行会话表。

### 8.3 状态

应用会话至少使用：

- `STARTING`
- `RUNNING`
- `CANCELLING`
- `WAITING`
- `TERMINAL_FAILED`
- `TERMINAL_COMPLETED`

单轮交互至少使用：

- `SUBMITTING`
- `RUNNING`
- `CANCELLING`
- `COMPLETED`
- `FAILED`
- `CANCELLED`

可恢复模型错误将单轮标记为 `FAILED`，随后把会话恢复为 `WAITING`。只有 eve 结构性 `session.failed` 才将应用会话标记为 `TERMINAL_FAILED`。

`turn.completed`、`turn.failed` 和 `turn.cancelled` 只表示单轮已经结算；客户端必须等到会话级 `session.waiting` 投影为 `conversation.status: WAITING` 后，才能允许继续发送。这样避免在 continuation token 尚未轮换完成时提前创建下一轮。

### 8.4 创建与异常恢复

- 首条消息先在事务中创建 `STARTING` 会话和 `SUBMITTING` 单轮，再调用 eve。
- eve 接受后写入 `sessionId`、加密 continuation token 和运行状态。
- `session.started` 事件处理器可根据服务 JWT 中的应用 ID 补写映射，处理 BFF 在 eve 接受后、响应落库前崩溃的情况。
- `session.started` 映射恢复必须同时兼容 Hook 先落库和 BFF 先完成接收两种顺序；相同映射重复执行保持幂等，身份、活动单轮、模型版本或 eve 会话不一致时失败关闭。
- eve turn ID 只在单个 eve 会话内唯一，数据库按应用会话 ID 与 eve turn ID 建立复合唯一约束，不能将 `turn_0` 等标识视为全局唯一。
- 创建失败且未启动 eve 时标记单轮失败；不得留下所有权未知的 eve 运行。
- 进程启动时扫描 `STARTING`、`RUNNING` 和 `CANCELLING` 记录，从 eve 持久流尾部校正状态。
- eve 暂时不可用时不伪造终止状态，保留待校正标记并拒绝冲突写操作。

## 9. 请求幂等与并发

### 9.1 `requestId`

- 客户端为每次明确发送生成新的随机 UUID `requestId`。
- 服务端对租户、用户和 `requestId` 建立唯一约束。
- 相同请求重试返回原 `conversationId`、`turnId` 和当前状态，不再次调用 eve。
- 用户点击“重新发送”必须生成新的 `requestId`，表示新的明确操作。
- 浏览器网络重试只能复用原 `requestId`。

### 9.2 数据库并发保护

- 同一会话通过条件更新或事务行锁保证只有一个活动单轮。
- 取消操作在取得会话锁后重新校验单轮仍处于活动状态；已经结算的单轮不能重新进入 `CANCELLING`。
- 创建或继续主会话前在事务中锁定应用用户记录，只统计该用户活动的主 Agent Turn，强制最多 3 个；Subagent 使用独立计数。
- 不使用模块全局变量作为权威并发状态。
- eve 边界调用不持有长数据库事务；先提交受约束状态，再调用外部运行时，并通过幂等记录和事件校正处理失败窗口。

## 10. BFF 到 eve 的认证

### 10.1 BFF 服务 JWT

- eve 标准会话路由和 `/eve/v1/info` 在开发与生产均只接受 BFF 短期 HMAC JWT。
- 删除 `localDev()` 浏览器放行；本地调试也必须使用受控服务令牌。
- 使用数据目录中的 `jwt-signing.key`，有效期 60 秒，不持久化、不返回浏览器。
- 固定验证签发者、Audience、`purpose`、签发时间和过期时间。
- Claim 携带经 P2 验证的用户、租户、角色、身份来源、应用会话、应用单轮和模型配置版本。
- eve 验证后将真实用户投影为 `session.auth.current`；首次创建时同时成为 `session.auth.initiator`。
- BFF 在签发前完成账号状态、租户、所有权、并发和模型可用性校验。
- 继续会话时同时验证 Claim 中的 `conversationId` 与目标 eve `sessionId` 映射。

### 10.2 令牌隔离

BFF 服务 JWT 与管理员原始流 JWT 可以共用 `jwt-signing.key`，但必须使用不同 Audience、`purpose` 和严格 Claim Schema。两种令牌互相不能访问对方路由。

## 11. 对话 API

建议公开应用接口：

| 方法与路径 | 作用 |
| --- | --- |
| `POST /api/conversations` | 使用首条消息创建应用会话和 eve 会话 |
| `GET /api/conversations/:conversationId` | 查询已知会话的当前控制状态 |
| `POST /api/conversations/:conversationId/messages` | 在等待中的自有会话发送下一条消息 |
| `POST /api/conversations/:conversationId/cancel` | 取消调用方观察到的活动单轮 |
| `GET /api/conversations/:conversationId/events?after=<cursor>` | 读取普通用户安全 NDJSON 流 |
| `POST /api/admin/conversations/:conversationId/stream-token` | 为管理员签发指定会话的原始流令牌 |

本地浏览器使用 Better Auth Cookie，并对写操作执行同源/CSRF 校验。嵌入页面使用 P2 Bearer 会话。两者均转换为同一个 `AuthenticatedPrincipal` 后进入相同应用服务。

所有请求体使用严格 Zod Schema。响应不包含 eve `sessionId`、`continuationToken`、BFF 服务 JWT、模型凭据或内部模型配置版本。

## 12. 普通用户安全事件流

### 12.1 公开事件

P3 定义应用自有协议，不直接删减并透传 eve 对象。允许的事件类型为：

- `conversation.status`
- `turn.started`
- `assistant.delta`
- `assistant.completed`
- `turn.completed`
- `turn.cancelled`
- `turn.failed`
- `authentication.expired`
- `heartbeat`

业务事件只包含必要的 `conversationId`、公开 `turnId`、公开 `blockId`、游标、时间和对应安全数据。

### 12.2 明确禁止

普通用户不得获得：

- `reasoning.*`
- `actions.requested`
- `action.result`
- `input.requested`
- `subagent.*`
- eve 步骤和尝试编号
- 原始错误、调用栈或提供商响应体
- eve `sessionId`、`continuationToken` 或内部请求 ID
- 模型提供商、模型版本、系统提示词或配置详情
- 未识别的未来事件

未知事件默认丢弃。普通管理员使用普通聊天视图时也接收同一安全投影。

### 12.3 游标与重连

- 业务事件游标基于 eve 原始事件绝对索引。
- 被过滤事件会造成游标跳号，但不会泄露内容或类型。
- 客户端传入最后成功处理的 `after` 游标，BFF 从下一个原始索引继续。
- 客户端按游标去重，允许断线边界发生重复投递。
- `heartbeat` 不推进 durable 游标，只携带当前已处理位置。
- 浏览器断开只停止传输，不取消服务端运行。
- P3 不以浏览器是否连接作为数据库状态更新条件；eve 事件处理器独立维护控制状态和 continuation token。

### 12.4 流式文本校正

- 每个回复块使用不暴露 eve 步骤编号的稳定公开 `blockId`。
- `assistant.delta` 同时携带新增文本和当前完整文本快照。
- 正常情况下前端追加增量；若新快照不再以前一版本开头，前端替换当前未完成草稿。
- 该规则处理模型已经输出部分文字后重试造成的内容重置，也支持断线后校正。
- 不向普通用户显示具体重试次数，只显示通用“正在重新尝试”状态。
- 已收到 `assistant.completed` 的完整块不因后续失败删除。
- 3 次均失败时移除当前尚未完成的草稿块并显示脱敏错误；管理员原始流保留全部事件。

### 12.5 错误映射

普通用户只接收稳定的公开错误，例如：

- `MODEL_UNAVAILABLE`
- `REQUEST_FAILED`
- `CONVERSATION_BUSY`
- `CONVERSATION_UNAVAILABLE`
- `AUTHENTICATION_EXPIRED`

公开错误不区分 API Key 是否错误、模型是否存在、内部响应内容或重试细节。管理员通过原始流和受控日志诊断。

## 13. 长连接身份撤销

- 安全流建立时验证当前身份、账号状态、租户和会话所有权。
- 流存续期间重新读取数据库权威会话状态。
- 发送业务事件前执行受限频率校验，校验缓存最长 2 秒，避免每个文本增量查询数据库。
- 无业务事件时通过心跳至少每 15 秒校验一次。
- 本项目执行禁用、会话撤销、密码重置、角色变化或嵌入令牌轮换时，主动关闭匹配的本机安全流；数据库复查作为兜底。
- 身份失效后发送不含内部原因的 `authentication.expired` 并关闭。
- 数据库不可用时失败关闭，不继续基于过期缓存发送事件。
- 嵌入令牌正常轮换后，旧流关闭，iframe 使用新令牌和最后游标重连；不取消 Agent 回复。

## 14. 管理员原始事件流

### 14.1 签发

- 管理员向 BFF 提交应用 `conversationId` 申请流令牌。
- BFF 每次重新读取当前管理员状态、角色和租户，并验证目标会话属于同一租户。
- 签发行为写入审计。
- 令牌有效期 60 秒，只限制建立连接，不因到期中断已建立流。
- 令牌绑定管理员、租户、应用会话、用途和 Audience。
- 令牌无状态，在有效期内可以重复连接同一会话，不建立一次性 `jti` 表。

### 14.2 读取

- 浏览器直接请求 `GET /eve/v1/admin/stream?startIndex=<n>`。
- `conversationId` 从签名 Claim 取得，不放入流 URL。
- 使用 `Authorization: Bearer`，不得放入查询参数、Cookie 或浏览器持久化存储。
- eve 根据应用会话映射解析真实 `sessionId`，返回未经 BFF 投影的原始 NDJSON。
- `startIndex` 使用 eve 原始绝对索引。断线后页面保存下一索引，并重新向 BFF 申请令牌。
- 浏览器使用 `fetch` 和 `ReadableStream`，不使用不能可靠附加 Bearer Header 的原生 `EventSource`。
- 页面关闭或切换会话时中止读取，不取消 Agent 运行。

管理员可读取本租户自己或其他用户会话的完整原始事件，但不能借此继续其他用户的会话。

## 15. 取消与身份变化

### 15.1 取消接口

- 请求必须携带 `conversationId` 和调用方观察到的公开 `turnId`。
- 所有者可取消自己的活动回复；管理员可取消本租户任意活动回复并写入审计。
- 管理员不能继续其他用户会话。
- BFF 调用 eve 前重新校验租户、所有权、账号状态和数据库当前活动单轮。
- 过期 `turnId` 返回 `409 TURN_CHANGED`，绝不取消调用方未观察到的新回复。
- 当前无活动回复时返回成功的 `no_active_turn`，重复取消保持幂等。
- eve 接受取消后先标记 `CANCELLING`；观察到 `turn.cancelled` 后才将会话恢复为 `WAITING`。
- 取消失败或超时时不伪造成功。
- 已产生的文本和外部副作用不回滚。

### 15.2 身份变化触发取消

以下操作除撤销认证会话外，还取消相关用户的活动回复：

- 禁用本地或嵌入用户。
- 修改本地用户角色。
- 管理员重置本地用户密码。
- 停用或删除嵌入客户端。

用户仅退出一个本地登录会话时不取消回复。嵌入会话正常续期轮换令牌时也不取消回复。

## 16. 失败与重试

- eve 在同一次回复内对所有模型调用错误统一最多尝试 3 次。
- BFF 和浏览器不叠加模型调用重试。
- 事件流断开只重连流，不重新发送消息。
- 3 次均失败后当前单轮标记 `FAILED`，eve 会话进入 `session.waiting`。
- 用户可以修复输入或等待管理员修改配置后，在原会话继续。
- 用户明确点击“重新发送”时创建新的 `requestId` 和新的单轮交互。
- 取消后的消息不自动重试。
- 只有结构性 eve 会话失败进入 `TERMINAL_FAILED`，此时旧会话只能查看，不能继续。

## 17. Markdown 与内容展示

- 用户输入和 Agent 回复均按受限 GitHub Flavored Markdown 渲染。
- 禁止原始 HTML，不使用 `dangerouslySetInnerHTML`。
- 链接只允许 `http`、`https` 和 `mailto`，外部链接使用新标签页及 `noopener noreferrer`。
- 拒绝 `javascript:`、`data:`、本地文件和未知协议。
- P3 不加载 Markdown 远程图片；P5/P6 通过受控文件组件显示图片和其他内容。
- 使用 KaTeX 渲染 `$...$` 行内公式和 `$$...$$` 块级公式，保持原始 HTML 禁用且不信任可执行 KaTeX 命令。
- 代码块显示语言标签和复制按钮；带语言标识的完整消息使用安全 React Token 节点进行语法高亮，流式草稿保持纯文本以避免每个增量重复解析。
- 流式回复按当前累计文本渲染，并由 `assistant.completed` 校正最终内容。

## 18. 页面与交互

### 18.1 本地主页

- 登录后的主页直接显示主 Agent 对话，不保留占位页。
- 桌面聊天页使用独立宽屏内容模式，消息正文与输入区继续保持受控阅读宽度；其他管理页面保留默认内容宽度。
- 未配置模型时禁用发送并显示明确状态；API 同时失败关闭。
- 页面提供新对话、发送、停止、重新发送和复制等必要操作。
- P3 只维护当前浏览器中的即时消息视图；P4 增加会话侧栏和权威历史。

### 18.2 嵌入页面

- `/embed` 在 P2 票据兑换成功后进入同一安全聊天组件。
- 使用精简 iframe 外壳，不显示项目导航或管理入口。
- Bearer 令牌只保存在运行内存，沿用 P2 的续期、撤销和刷新规则。
- P9 再把该体验整理为正式可复用组件和接入文档。

### 18.3 管理员执行详情

- 管理员默认聊天内容与普通用户相同。
- 显式开启“执行详情”后才申请原始流令牌并直连 eve。
- 桌面使用可调整宽度侧栏，移动端使用独立全屏视图或标签页。
- P3 支持事件顺序、类型、时间、展开原始 JSON 和自动跟随。
- Tool 和 Subagent 的专用能力与验收留到 P5/P7；原始 JSON 视图保持可用。当前路线不启用终端，未来若重新启用则复用相同原始事件视图。

## 19. 模型管理页面与 API

## 20. 审计与日志

- 管理员原始流令牌签发。
- 管理员查看或取消其他用户会话。

- 会话越权访问拒绝的必要非敏感元数据。

普通日志不记录完整用户输入、模型输出、系统提示词、API Key、令牌或 continuation token。允许记录请求 ID、应用会话 ID、公开单轮 ID、模型配置版本 ID、耗时、状态和脱敏错误码。

## 23. 环境与验收前提

### 23.1 开发环境

- WSL/Linux、Node.js 24 和 npm。
- 已完成 P1/P2 迁移的 PostgreSQL 应用数据库。
- 独立 `P3_TEST_DATABASE_URL`。
- 可写的项目数据目录及现有三类独立密钥。
- 可匿名下载且校验值与第 6.4 节一致的固定 eve Release 制品。
- 浏览器，用于本地、管理员和嵌入流程验收。
- 最终真实验收时可访问管理员配置的 OpenAI Chat Completions 兼容模型。

P3 不依赖 S3、Redis、SMTP、知识库、特定宿主系统或环境变量模型凭据。

### 23.2 自动化测试隔离

- 数据库与 HTTP 验收未配置 `P3_TEST_DATABASE_URL` 时立即拒绝运行。
- `P3_TEST_DATABASE_URL` 与 `DATABASE_URL` 指向同一数据库时立即拒绝运行。
- 每次测试使用随机租户、用户、会话、配置和请求标识，并在成功或失败后清理。
- 自动化测试启动本地假的 Chat Completions 兼容服务，不访问真实提供商。
- 假服务覆盖非流式测试响应、流式增量、部分输出后失败、重试、超时、错误体和可选 API Key。
- 测试不得读取、写入或打印管理员真实凭据。

### 23.3 真实模型验收

- 管理员通过页面填写 Base URL、可选 API Key、模型名称和可选上下文窗口。
- 人工点击连通性测试并确认完整输出可见。
- 使用真实模型完成首条消息、后续消息、取消、断线重连和配置切换。
- 人为配置错误凭据，确认最多 3 次失败后原会话回到等待；修复配置后同一会话可以继续。

真实模型不可用不阻塞单元测试、类型检查、构建和模拟协议测试，但会阻塞“P3 已完成”的最终结论。

## 24. 验收标准

### 24.1 eve 修改

- 交互式对话的所有模型错误统一最多尝试 3 次。
- 尝试耗尽后产生 `turn.failed -> session.waiting`，原 continuation token 可继续。
- 替换模型凭据后原会话下一条消息成功。
- 任务模式和结构性工作流失败保持终止语义。
- eve 对应单元测试、类型检查、文档检查和必要 changeset 完成。

### 24.2 自动化检查

- `npm run typecheck`
- `npm test`
- `npm run db:check`
- `npm run test:p3:database`
- `npm run test:p3:http`
- `npm run build`
- `git diff --check`

数据库测试至少覆盖：

- 模型配置版本并发更新和当前指针。
- 凭据加解密、关联数据、错误密钥和凭据安全清理。
- 会话所有权不可变和跨租户拒绝。
- 同会话并发提交、用户跨会话最多 3 个活动主 Agent 回复；Subagent 不占用该额度。
- `requestId` 幂等及创建响应丢失恢复。
- continuation token 密文存储和轮换。
- 单轮模型版本锁定及下一条消息切换新版本。
- 取消状态、过期 `turnId` 和无活动回复幂等。

HTTP 和协议测试至少覆盖：

- 本地 Cookie 与嵌入 Bearer 共用同一对话服务。
- 普通用户不能直接访问 eve 标准路由或管理员原始流。
- BFF 服务 JWT 与管理员流 JWT 不能互换。
- 普通用户事件允许列表逐类测试，未知事件失败关闭。
- 断线游标恢复、重复事件去重和文本快照校正。
- API Key、eve 句柄、内部事件和原始错误不出现在普通响应。
- 管理员令牌只读取绑定会话和租户。
- 身份撤销、嵌入令牌轮换和数据库失效会关闭安全流。
- 配置错误、超时和部分输出失败遵守统一重试与会话恢复语义。

### 24.3 浏览器验收

- 本地普通用户可从主页创建、继续和取消主 Agent 对话。
- 管理员默认看到安全聊天，开启执行详情后看到原始事件。
- 管理员无法以其他用户身份继续会话。
- 嵌入用户完成票据兑换后使用同一安全聊天组件。
- 嵌入续期轮换时旧流关闭，新流从游标继续，回复不被取消。
- 用户和 Agent Markdown 正确渲染且原始 HTML 不执行。
- 外部图片不自动加载，危险链接协议不可点击。
- 桌面和移动布局无重叠、截断或不可操作控件。
- 未配置模型、模型失败、身份过期、并发限制、取消和网络断开均有明确可恢复状态。

### 24.4 验收结论与延期项

P3 于 2026-08-03 完成实施和阶段验收。已确认真实模型配置与对话、多轮上下文、取消、断线重连、配置修复后原会话继续、管理员原始执行详情、本地普通用户对话、Markdown、LaTeX、代码高亮及最新桌面与移动布局。

以下人工浏览器验收经确认延期，不阻塞 P3 完成和 P4 启动：

- 嵌入票据兑换、嵌入对话、续期轮换、旧流关闭和游标重连的完整浏览器验收延期至 P9。P3 已实现的协议、授权和自动化 HTTP 覆盖保留，P9 不得绕过或重新建立平行身份协议。
- 未配置模型、模型失败、身份过期和并发限制等异常状态的完整浏览器矩阵延期至 P10。P3 已通过的服务端限制、安全投影和自动化验收仍为后续验收基线。

上述延期仅调整人工浏览器验收时点，不表示删除、降级或放弃 P3 已实现的功能与安全边界。

### 24.5 阶段完成条件

- P3 使用确定的已修复 eve 构建，不依赖 `node_modules` 手工修改或本地路径依赖。
- 真实 OpenAI Chat Completions 兼容模型已完成一次端到端验收。
- 普通用户从网络响应中无法取得任何禁止的原始事件或 eve 句柄。
- 管理员原始流、BFF 标准路由和普通安全流三条信任边界互不替代。
- 会话创建、继续、取消、重连、身份撤销和配置切换均经过自动化验证；浏览器验证按第 24.4 节的已验收范围和延期边界执行。
