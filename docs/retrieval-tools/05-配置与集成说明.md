## 1. 配置参数（讯飞星火 MaaS）

检索工具当前用**讯飞星火 MaaS**（OpenAI 兼容格式），开通了 Qwen3-8B 的 Embedding 和 Reranker。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| **根地址** | `https://maas-api.cn-huabei-1.xf-yun.com` | 华北 1 节点 |
| **Embedding 路径** | `POST /v2/embeddings` | 文本→向量 |
| **Rerank 路径** | `POST /v2/rerank` | 召回结果精排 |
| **鉴权** | `Authorization: Bearer <XFYUN_API_KEY>` | HTTP 头，Bearer Token |
| **Embedding 模型 ID** | `xop3qwen8bembedding` | Qwen3-Embedding-8B |
| **Rerank 模型 ID** | `xop3qwen8breranker` | Qwen3-Reranker-8B |
| **向量维度** | **4096**（可调 32~4096） | Qwen3-8B 原生 4096 维；讯飞默认压成 768，已配 `dimensions:4096` 用原生最高维。改维度需重建索引 + 同步建表维度 |
| **超时** | 默认 15000ms | 可在 `XFYUN_DEFAULT_CONFIG` 调 |
| **QPS 限流** | **20**（控制台实测） | 入库流水线按此控制节奏，避免限流超时 |
| **每批条数** | 16（默认） | 批量嵌入按此切分，兼顾吞吐与不超限 |

> 以上参数集中在 [`src/server/retrieval/retrieval.config.ts`](../../src/server/retrieval/retrieval.config.ts) 的 `xfyunConfig`，改那个文件即可，不用翻实现代码。密钥（APIKey）仍走 `.env`，不进配置文件。
>
> ⚠️ **入库必须分批**：讯飞 QPS/并发上限 20，一次性大批量嵌入会触发限流导致超时（929 片段一次性发会失败，分批 16 条则稳定通过）。入库流水线（02）已按 `batchSize` 分批、按 `qps` 控制节奏。

### 1.0 配置去向（改参数前先看）

检索工具的配置分三类，**各归各位，不要混**：

| 配置类型 | 放在哪 | 为什么 | 例子 |
| --- | --- | --- | --- |
| **密钥**（敏感） | `.env`（不进仓库） | 泄露风险高，等于密码 | `XFYUN_API_KEY` |
| **可调参数**（普通） | [`retrieval.config.ts`](../../src/server/retrieval/retrieval.config.ts)（进仓库） | 不敏感，集中好改、有 git 记录 | 维度、批次、超时 |
| **实现逻辑** | 代码里（`embedders/`） | 程序行为，不该随便改 | 怎么调讯飞接口 |

**调整参数只动一个文件**：[`src/server/retrieval/retrieval.config.ts`](../../src/server/retrieval/retrieval.config.ts)。该文件内容（节选）：

```ts
export const xfyunConfig = {
  baseUrl: "https://maas-api.cn-huabei-1.xf-yun.com",
  apiKeyEnv: "XFYUN_API_KEY",          // 密钥走 .env，这里只写变量名
  embeddingModel: "xop3qwen8bembedding",
  rerankModel: "xop3qwen8breranker",
  embeddingDimensions: 4096,            // 维度（Qwen3-8B 原生 4096，可调 32~4096）
  embeddingBatchSize: 16,               // 每批条数（受 QPS 限制）
  timeoutMs: 15000,                     // 单次请求超时
} as const;

export const retrievalConfig = {
  recallTopK: 20,        // 向量召回数量（reranker 前粗筛）
  finalTopN: 5,          // reranker 精排后最终返回条数
  chunkMaxChars: 500,    // 切片大小（每段字符数）
  chunkOverlap: 50,      // 切片重叠
} as const;
```

> ⚠️ 改 `embeddingDimensions` 的连锁反应：维度变了 → 已入库的向量全部作废（需重新入库）+ 建表（02）的向量列维度要同步改。所以**定了就别轻易改**。

### 1.1 APIKey（密钥）—— 走私发，不进仓库

本项目是共享项目，但 **key 仍不写进仓库**（`.env` 默认被 git 忽略，写进去也 push 不上去）。采用「私发 + 本地填写」的方式：

**集成方（同事）拿到代码后，做两步：**
1. 找项目维护者**私要**讯飞 MaaS 的 `APIKey`。
2. 在 `baigong-agent/` 目录下（与 `package.json` 同级）建一个 `.env` 文件，填入：
   ```
   XFYUN_API_KEY=<维护者私发给你的 key>
   ```

> - `.env.example`（进仓库）只是说明，里面是**空值**，告诉集成方"有这个配置项、key 找维护者要"。
> - `.env`（不进仓库，被 `.gitignore` 的 `.env*` 规则忽略）才是实际生效的真值。
> - 仓库里只有说明，没有真 key；key 通过私聊（微信/钉钉等）单独传递。
> - **生产环境**：改为由智能体管理后台加密配置（遵守 P0 §8），不用 `.env`。

## 2. 检索能力一览（集成方可调用的接口）

检索核心逻辑都在 `src/server/retrieval/`（lib 层），提供两个能力：

### 2.1 嵌入（Embedding）—— 把文本变向量

```ts
import { embedder } from "@/server/retrieval/embedder-instance";

// 单条（查询嵌入，高频）
const { vector, dim } = await embedder.embed("用户的查询");

// 批量（入库嵌入，一次性）
const results = await embedder.embedBatch(["文档片段1", "文档片段2", ...]);
```

### 2.2 重排（Reranker）—— 对召回结果精排

```ts
import { reranker } from "@/server/retrieval/reranker-instance";

const items = await reranker.rerank({
  query: "用户的查询",
  documents: ["召回片段1", "召回片段2", ...],  // 召回出的几十段
  topN: 5,                                       // 只要前 5 条（可选）
});
// items 已按相关性分数降序排序
```

## 3. 如何集成进 eve 智能体（两种方式）

> 关键设计：核心逻辑在 `lib`，工具是薄包装。所以 agentic 和单独调用共用同一套逻辑。

### 方式 A：agentic 自动调用（模型自己决定调哪个工具）

把下面的工具文件放进 `agent/tools/`（文件名即工具名，eve 自动发现）。详见 [`04-eve工具封装.md`](./04-eve工具封装.md)：

```
agent/tools/vector_search.ts     向量检索（调 embedder）
agent/tools/hybrid_search.ts     混合检索（调 embedder + reranker 精排）
...（关键词检索等）
```

模型根据用户问题，自己选用哪个工具。**这是 Agentic RAG 的核心**——检索不再是固定管道。

### 方式 B：单独调用（代码直接调，不经模型）

在任意 Next.js API 路由 / 业务代码里直接 import：

```ts
// 例：一个独立的检索接口
import { reranker } from "@/server/retrieval/reranker-instance";
import { embedder } from "@/server/retrieval/embedder-instance";

export async function POST(req: Request) {
  const { query } = await req.json();
  const { vector } = await embedder.embed(query);
  // ... 用 vector 做向量检索 ...
  // ... 对结果用 reranker 精排 ...
  return Response.json({ ok: true });
}
```

## 4. 文件清单（交付物）

```
src/server/retrieval/
  ├─ embedder.ts                 Embedder 接口（不依赖具体厂商）
  ├─ embedder-instance.ts        嵌入器统一出口（当前=讯飞）
  ├─ reranker.ts                 Reranker 接口
  ├─ reranker-instance.ts        Reranker 统一出口（当前=讯飞）
  └─ embedders/
       └─ xfyun-maas.ts          讯飞 MaaS 实现（Embedding + Rerank）

配置：
  └─ .env                        开发期放 XFYUN_API_KEY（本地，不进仓库）
  └─ .env.example                占位说明（进仓库，空值）
```

> **集成方只需要**：① 填好 `XFYUN_API_KEY`；② 按 §3 选一种集成方式。核心检索逻辑已封装好，不用改。

## 6. 切换后端（未来）

若要从讯飞切到自建 Qwen3 或别家：
1. 在 `embedders/` 下写新实现（满足 `Embedder` / `Reranker` 接口）。
2. 改 `embedder-instance.ts` / `reranker-instance.ts` 指向新实现。
3. **重建已入库的向量**（换模型 = 旧向量作废）。
上层调用代码和集成方式**完全不变**。
