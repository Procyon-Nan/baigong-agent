# 01 · 嵌入与重排序服务（Embedding + Rerank）

> 本篇只讲本次实际落地的一件事：**如何把文本变成向量（嵌入），以及如何对召回结果做精排（重排序）**。
> 这是后续向量检索的两块数据基础。存储入库、检索调度、eve 封装等属于后续模块，不在本篇范围内。

---

## 1. 它是什么

向量检索需要两个能力，本模块都提供了：

| 能力 | 作用 | 触发时机 |
| --- | --- | --- |
| **嵌入 Embedding** | 把一段文本变成一串数字（向量），相似文本的向量也相近 | ① 文档入库时（批量，一次性）<br>② 用户提问时（单条，高频） |
| **重排序 Rerank** | 对粗筛召回的一批候选文档，按与查询的相关性重新打分排序 | 召回之后、返回给用户之前（精排） |

一条检索链路长这样：

```
用户提问
  │
  ├─① embed(问题)          → 得到问题向量
  │
  ├─② 向量库粗筛召回 Top-K   → 拿到一批候选文档（后续模块做）
  │
  └─③ rerank(问题, 候选文档) → 精排出最相关的 Top-N 返回   ← 本模块
```

> 本次只交付 ①③ 的服务封装（含讯飞 MaaS 实现），② 由后续「存储与入库 / 检索引擎」模块接手。

---

## 2. 用什么模型

当前后端实现：**讯飞星火 MaaS**（OpenAI 兼容接口）。

| 能力 | 模型 | 讯飞 model id |
| --- | --- | --- |
| 嵌入 | Qwen3-Embedding-8B | `xop3qwen8bembedding` |
| 重排序 | Qwen3-Reranker-8B | `xop3qwen8breranker` |

> ⚠️ **铁律**：入库嵌入和查询嵌入必须用**同一个模型、同一维度**，否则相似度算出来是错的。
> 换模型 = 已入库向量全部作废，需重建索引。

---

## 3. 接口设计（核心：可切换的抽象层）

嵌入和重排序都抽成了**接口**，后端实现可切换（讯飞 / 自建 Qwen3 / 别家），上层代码只认接口。

### 3.1 嵌入接口 `Embedder`

定义在 `src/server/retrieval/embedder.ts`：

```ts
export interface EmbedResult {
  vector: number[];  // 向量
  dim: number;       // 维度（必须和建表时向量列维度一致）
  model: string;     // 实际使用的模型名（便于排查）
}

export interface Embedder {
  readonly model: string;
  readonly dim: number;
  embed(text: string): Promise<EmbedResult>;            // 查询嵌入（单条、高频）
  embedBatch(texts: string[]): Promise<EmbedResult[]>;  // 入库嵌入（批量、一次性）
}
```

### 3.2 重排序接口 `Reranker`

定义在 `src/server/retrieval/reranker.ts`：

```ts
export interface RerankInput {
  query: string;        // 用户问题
  documents: string[];  // 召回回来的候选文档
  topN?: number;        // 可选：只返回前 N 条
}

export interface RerankItem {
  index: number;        // 在原 documents 中的下标
  score: number;        // 相关性分数（已降序排好）
}

export interface Reranker {
  rerank(input: RerankInput): Promise<RerankItem[]>;
}
```

### 3.3 上层怎么用

上层只 import 实例，**不直接碰具体实现**：

```ts
import { embedder } from "@/server/retrieval/embedder-instance";
import { reranker } from "@/server/retrieval/reranker-instance";

const { vector } = await embedder.embed("怎么报销");
const top = await reranker.rerank({ query: "怎么报销", documents: [...], topN: 3 });
```

**切换后端**（如换成自建 Qwen3）：只改 `embedder-instance.ts` / `reranker-instance.ts` 这两个出口文件里的 import 和工厂函数，**上层检索代码一行不动**。

## 5. 配置参数（`retrieval.config.ts`）

所有可调参数集中在 `retrieval.config.ts`，含义如下：

### 5.1 讯飞 / 模型相关 `xfyunConfig`

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `baseUrl` | `https://maas-api.cn-huabei-1.xf-yun.com` | 讯飞 MaaS 根地址（华北1节点） |
| `apiKeyEnv` | `"XFYUN_API_KEY"` | APIKey 的环境变量名（真值放 `.env`，不写死） |
| `embeddingModel` | `xop3qwen8bembedding` | 嵌入模型 id |
| `rerankModel` | `xop3qwen8breranker` | 重排序模型 id |
| `embeddingDimensions` | `4096` | 嵌入输出维度。Qwen3-8B 支持 32~4096。⚠️ 改维度 = 已入库向量作废，建表向量列维度须同步改 |
| `embeddingBatchSize` | `16` | 批量嵌入每批条数。讯飞 QPS 上限 20，留余量避免限流 |
| `timeoutMs` | `15000` | 单次请求超时（毫秒） |

### 5.2 检索参数 `retrievalConfig`

> 这些参数为后续检索引擎模块预留，本模块的 reranker 已支持 `topN` 透传。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `recallTopK` | `20` | 向量召回数量（粗筛，reranker 前先召回这么多） |
| `finalTopN` | `5` | reranker 精排后最终返回条数 |
| `chunkMaxChars` | `500` | 切片大小（每段字符数） |
| `chunkOverlap` | `50` | 切片重叠（避免切断语义） |

## 6. 密钥配置（`.env`）

APIKey **不进仓库**，通过环境变量注入：

```bash
# 在项目根目录的 .env 文件里写一行（与 package.json 同级，.env 不进 git）：
XFYUN_API_KEY=<你的讯飞 MaaS APIKey>
```

`.env.example` 里有对应占位说明。生产环境改为由管理后台加密配置，不使用此环境变量。

---

## 7. 验证

确认嵌入与重排序链路可用：

```bash
# 先确保本地 .env 里填了 XFYUN_API_KEY
node --import tsx scripts/verify-retrieval.ts
```

脚本会分别测试 ① embedding（返回向量维度和前几个数字）和 ② rerank（返回排序结果），全过则打印 `✅ 全部通过`。
