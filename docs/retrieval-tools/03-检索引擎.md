# 03 · 检索引擎（找出最像的文档片段）

> 文档已经入库（02）。本篇讲：**用户问一句话，怎么从库里把最相关的几段捞出来。**
> 这是整个检索工具的"心脏"，写成**纯函数放在 `lib/`**，不依赖 eve——这样 agentic 和单独调用都能用（见 04）。

---

## 1. 三种检索方式

| 方式 | 原理 | 适合的问题 |
| --- | --- | --- |
| **向量检索** | 算"意思有多接近" | "怎么处理客户投诉"（概念类） |
| **关键词检索** | 算"字面有没有出现" | "工号 10032"（专名、编号、代码） |
| **混合检索** | 两者结合（RRF 融合） | 综合问题，拿不准时用 |

**为什么都要？** 因为没有一种检索能搞定所有问题：
- 问"报销政策"用向量（意思接近）
- 问"员工编号 10032"用关键词（精确匹配，向量会漏）
- 拿不准就混合

---

## 2. 统一的输入输出（接口）

所有检索函数共用一套类型，让上层（工具封装、API）调用方式一致：

```ts
// src/server/retrieval/types.ts

/** 检索输入 */
export interface SearchInput {
  query: string;                       // 用户问题
  tenantId: string;                    // 租户（多租户隔离，必须从身份来）
  userId?: string;                     // 用户（做可见性过滤）
  collectionSlug?: string;             // 限定某个知识库，不填则查全部可见
  limit?: number;                      // 返回条数，默认 5
}

/** 单条命中结果 */
export interface SearchHit {
  chunkId: string;
  documentId: string;
  filename: string;
  text: string;                        // 命中的文档片段原文
  score: number;                       // 相似度/相关度分数
  metadata?: Record<string, unknown>;  // 页码、标题等
}

/** 检索结果 */
export interface SearchResult {
  query: string;
  hits: SearchHit[];
}
```

## 3. 向量检索（语义）

思路：把 query 嵌入成向量 → 在库里按余弦相似度找最近的几条 → 按 `tenant_id` 过滤。

```ts
// src/server/retrieval/vector-search.ts
import { embedder } from "./embedder-instance";
import type { SearchInput, SearchHit, SearchResult } from "./types";
// import { db } from "../db/client";
// import { documentEmbeddings, documentChunks, documents } from "../db/schema/knowledge";
// import { desc, sql, eq, and } from "drizzle-orm";

/**
 * 向量检索：按语义相似度找最相关的文档片段。
 * 纯逻辑函数，放 lib，不依赖 eve。
 */
export async function vectorSearch(input: SearchInput): Promise<SearchResult> {
  const limit = input.limit ?? 5;

  // 1. 把 query 嵌入成向量
  const { vector } = await embedder.embed(input.query);

  // 2. 在库里按余弦相似度查（带 tenant 过滤）
  //    pgvector 的距离算子：<=> 是余弦距离，1 - <=> = 相似度
  //    伪代码（用 Drizzle 的 sql 模板写实际查询）：
  //
  //    const rows = await db.execute(sql`
  //      SELECT e.chunk_id, e.embedding <=> ${vector} AS distance,
  //             c.text, c.metadata, d.filename, d.id AS document_id
  //      FROM document_embeddings e
  //      JOIN document_chunks c ON c.id = e.chunk_id
  //      JOIN documents d ON d.id = c.document_id
  //      WHERE e.tenant_id = ${input.tenantId}
  //        ${input.collectionSlug ? sql`AND d.collection_id = ...` : sql``}
  //      ORDER BY e.embedding <=> ${vector}
  //      LIMIT ${limit}
  //    `);

  const hits: SearchHit[] = [];  // = rows.map(... 把 distance 转成 score)

  return { query: input.query, hits };
}
```

> **关键**：`WHERE e.tenant_id = ${input.tenantId}` 这一行是多租户隔离的命脉。`tenantId` 只能从身份上下文来（见 04），**绝不能让模型在参数里传**。

## 5. 混合检索（RRF 融合）

思路：**同时**跑向量和关键词两路 → 用 RRF（倒数排名融合）合并 → 不依赖分数标定，工程简单、效果稳定。

```ts
// src/server/retrieval/hybrid-search.ts
import { vectorSearch } from "./vector-search";
import { keywordSearch } from "./keyword-search";
import type { SearchInput, SearchHit, SearchResult } from "./types";

/**
 * 混合检索：向量 + 关键词并行召回，RRF 融合。
 * 拿不准问题类型时用这个，综合效果最好。
 */
export async function hybridSearch(input: SearchInput): Promise<SearchResult> {
  const limit = input.limit ?? 5;

  // 两路并行召回
  const [vecRes, kwRes] = await Promise.allSettled([
    vectorSearch(input),
    keywordSearch(input),
  ]);

  // 任一路失败都能降级（比如嵌入服务挂了，向量那路 reject，关键词照常出结果）
  const vecHits = vecRes.status === "fulfilled" ? vecRes.value.hits : [];
  const kwHits = kwRes.status === "fulfilled" ? kwRes.value.hits : [];

  // RRF 融合：按"在各自结果里的排名"算分，排名越靠前分越高
  const K = 60;  // RRF 常数
  const scoreMap = new Map<string, { hit: SearchHit; score: number }>();

  const addRank = (hits: SearchHit[]) => {
    hits.forEach((hit, rank) => {
      const existing = scoreMap.get(hit.chunkId);
      const rrf = 1 / (K + rank + 1);
      if (existing) existing.score += rrf;
      else scoreMap.set(hit.chunkId, { hit, score: rrf });
    });
  };
  addRank(vecHits);
  addRank(kwHits);

  const hits = [...scoreMap.values()]
    .sort((a, b) => b.score - a.score)
    .slice(0, limit)
    .map(({ hit, score }) => ({ ...hit, score }));

  return { query: input.query, hits };
}
```

> **这里体现了工具化检索的降级优势**：`Promise.allSettled` + 降级，向量服务挂了不影响关键词那路，混合检索仍能返回结果。

## 8. 可选进阶（后续再说）

- **重排（rerank）**：召回后再用 rerank 模型精排，提升准确率。先不引入，跑通基础检索后再加。
- **查询改写**：把用户口语化问题改写成更适合检索的 query。进阶项。
- **元数据过滤**：按文件类型、时间范围等过滤。`SearchInput` 已预留 `collectionSlug`，按需扩展。
