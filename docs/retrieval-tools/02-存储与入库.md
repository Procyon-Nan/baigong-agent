# 02 · 存储与入库（把文档变成向量存进库）

> 上一篇把文本变成了向量。本篇讲：**这些向量存哪、文档怎么自动切片入库。**

---

## 1. 存在哪：PostgreSQL + pgvector

项目已经用 PostgreSQL，我们给它装个 **pgvector** 插件，让它能存向量。**一个库同时存：关系数据、向量、全文检索**，不用引入额外服务。

### 1.1 装插件

```sql
-- 在你的 PostgreSQL 里执行一次（连接服务器上的库时跑）
CREATE EXTENSION IF NOT EXISTS vector;
```

> 本地开发测试时，用 Docker 起一个自带 pgvector 的 PG 即可（见文末附录）。

---

## 2. 表结构（用 Drizzle 定义）

遵循项目已有模式（参考 `src/server/db/schema/tenants.ts`）。**所有表都带 `tenant_id`**（多租户隔离的命脉）。

### 2.1 四张表的关系

```
knowledge_collections（知识库）
  ├── documents（文档，一个库有多个文档）
  │     └── document_chunks（切片，一个文档切成多段）
  │           └── document_embeddings（向量，每段切片一个向量）
```

### 2.2 Schema 代码骨架

新增文件 `src/server/db/schema/knowledge.ts`：

```ts
// src/server/db/schema/knowledge.ts
import { sql } from "drizzle-orm";
import { check, pgTable, timestamp, uuid, varchar, text, integer, jsonb, index } from "drizzle-orm/pg-core";
// 注意：vector 类型需要 drizzle 的 vector 列支持，新版 drizzle-orm 已内置 vector
import { vector } from "drizzle-orm/pg-core";
import { tenants } from "./tenants";

/** 知识库集合（一个租户可有多个库） */
export const knowledgeCollections = pgTable("knowledge_collections", {
  id: uuid("id").defaultRandom().primaryKey(),
  tenantId: uuid("tenant_id").notNull().references(() => tenants.id),
  name: varchar("name", { length: 120 }).notNull(),
  slug: varchar("slug", { length: 63 }).notNull(),
  description: text("description"),
  embeddingModel: varchar("embedding_model", { length: 120 }).notNull(),  // 记录用哪个模型嵌入的
  embeddingDim: integer("embedding_dim").notNull(),                       // 维度
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  index("kc_tenant_idx").on(t.tenantId),
]);

/** 原始文档记录 */
export const documents = pgTable("documents", {
  id: uuid("id").defaultRandom().primaryKey(),
  tenantId: uuid("tenant_id").notNull().references(() => tenants.id),
  collectionId: uuid("collection_id").notNull().references(() => knowledgeCollections.id),
  ownerId: uuid("owner_id").notNull(),            // 上传者
  filename: varchar("filename", { length: 255 }).notNull(),
  mime: varchar("mime", { length: 100 }).notNull(),
  size: integer("size").notNull(),
  status: varchar("status", { length: 30 }).notNull().default("pending"), // pending/parsed/failed
  error: text("error"),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  index("doc_tenant_idx").on(t.tenantId),
  index("doc_collection_idx").on(t.collectionId),
]);

/** 切片（检索单元） */
export const documentChunks = pgTable("document_chunks", {
  id: uuid("id").defaultRandom().primaryKey(),
  tenantId: uuid("tenant_id").notNull().references(() => tenants.id),
  documentId: uuid("document_id").notNull().references(() => documents.id),
  collectionId: uuid("collection_id").notNull().references(() => knowledgeCollections.id),
  ordinal: integer("ordinal").notNull(),           // 切片在文档中的序号
  text: text("text").notNull(),                    // 切片原文
  metadata: jsonb("metadata"),                     // 页码、标题、位置等
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  index("chunk_doc_idx").on(t.documentId),
  index("chunk_tenant_idx").on(t.tenantId),
]);

/** 向量（单独建表，便于换模型重建） */
export const documentEmbeddings = pgTable("document_embeddings", {
  id: uuid("id").defaultRandom().primaryKey(),
  tenantId: uuid("tenant_id").notNull().references(() => tenants.id),
  chunkId: uuid("chunk_id").notNull().references(() => documentChunks.id),
  collectionId: uuid("collection_id").notNull().references(() => knowledgeCollections.id),
  embedding: vector("embedding", { dimensions: 4096 }).notNull(),  // ⚠️ 维度要和 embedder 的 dimensions 一致（Qwen3-8B 原生 4096，可调 32~4096）
  model: varchar("model", { length: 120 }).notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  index("emb_chunk_idx").on(t.chunkId),
  index("emb_tenant_idx").on(t.tenantId),
]);

export type KnowledgeCollection = typeof knowledgeCollections.$inferSelect;
export type Document = typeof documents.$inferSelect;
export type DocumentChunk = typeof documentChunks.$inferSelect;
export type DocumentEmbedding = typeof documentEmbeddings.$inferSelect;
```

> ⚠️ **关键**：`embedding` 列的 `dimensions: 4096` 必须和 embedder 的 `dimensions` 配置一致（Qwen3-Embedding-8B 原生 4096，讯飞默认压成 768，我们在 [xfyun-maas.ts](../../src/server/retrieval/embedders/xfyun-maas.ts) 配了 `dimensions: 4096` 用原生最高维）。两边对不上，写入会报错。**改维度 = 已入库向量作废，需重建索引**；建表维度也要同步改。

### 2.3 加 HNSW 向量索引（检索快慢的关键）

迁移生成后，手动在迁移 SQL 里加 HNSW 索引（召回质量优于默认的 IVFFlat）：

```sql
CREATE INDEX emb_vector_idx ON document_embeddings
  USING hnsw (embedding vector_cosine_ops);
```

### 2.4 加全文检索列（给关键词检索用）

切片表加一个 tsvector 列（中文分词见 §4）：

```sql
ALTER TABLE document_chunks ADD COLUMN tsv tsvector;
CREATE INDEX chunk_tsv_idx ON document_chunks USING gin (tsv);
```

## 4. 中文分词（关键词检索要用）

PostgreSQL 默认分词对中文不友好。**建议应用层分词**（部署简单，契合单实例自托管）：入库和查询都在代码里用 `nodejieba` 切词，再写入 `tsv` 列。

```ts
// src/server/retrieval/tokenizer.ts  （入库和查询共用这一个文件，保证一致）
import { cut } from "nodejieba";   // 需 npm i nodejieba

/** 把中文文本切成词，拼成 tsquery 格式 */
export function tokenize(text: string): string {
  return cut(text, true).filter((w) => w.trim()).join(" ");
}
```

## 5. 入库流水线（文档 → 切片 → 向量 → 入库）

新增 `src/server/indexing/`，把"一份文档进库"拆成清晰几步：

```
拿文档 → 解析出纯文本 → 清洗 → 切片(每段约500字、重叠50) → 分词填tsv → 批量嵌入 → 写库
```

### 5.1 切片函数（核心逻辑，纯函数放 lib）

```ts
// src/server/indexing/chunker.ts
/**
 * 把一段长文本切成带重叠的小段。
 * 重叠（overlap）保证切片边界处的语义不丢失。
 */
export interface Chunk {
  ordinal: number;
  text: string;
  metadata?: Record<string, unknown>;
}

export function chunkText(
  text: string,
  options: { maxChars?: number; overlap?: number } = {}
): Chunk[] {
  const maxChars = options.maxChars ?? 500;
  const overlap = options.overlap ?? 50;
  const chunks: Chunk[] = [];
  let i = 0;
  let ordinal = 0;
  while (i < text.length) {
    const end = Math.min(i + maxChars, text.length);
    const slice = text.slice(i, end).trim();
    if (slice) {
      chunks.push({ ordinal: ordinal++, text: slice });
    }
    if (end >= text.length) break;
    i = end - overlap;   // 往后退 overlap，形成重叠
  }
  return chunks;
}
```

### 5.2 入库主流程（骨架）

```ts
// src/server/indexing/ingest.ts
import { embedder } from "../retrieval/embedder-instance";
import { chunkText } from "./chunker";
import { tokenize } from "../retrieval/tokenizer";
// import { db } from "../db/client";  // 项目已有的 Drizzle 客户端

/**
 * 把一份文档入库：解析 → 切片 → 嵌入 → 写库。
 * identity：当前租户/所有者（多租户隔离用）
 */
export async function ingestDocument(input: {
  tenantId: string;
  ownerId: string;
  collectionId: string;
  filename: string;
  text: string;            // 解析后的纯文本（解析器后续做，这里先假定已拿到）
}): Promise<{ chunkCount: number }> {
  // 1. 切片
  const chunks = chunkText(input.text);

  // 2. 批量嵌入——必须分批（讯飞 QPS/并发限 20，一次发太多会超时）
  //    按配置的 batchSize（默认 16）切批，逐批嵌入；如需更稳可按 qps 限速
  const BATCH = 16;
  const embeddings = [];
  for (let i = 0; i < chunks.length; i += BATCH) {
    const batch = chunks.slice(i, i + BATCH).map((c) => c.text);
    embeddings.push(...await embedder.embedBatch(batch));
  }

  // 3. 写库（伪代码，用项目的 db）
  //    - 先写 documents 表（状态 parsed）
  //    - 再批量写 document_chunks（含分词后的 tsv）
  //    - 再批量写 document_embeddings（向量）
  // ...具体 SQL 用 Drizzle 的 insert 完成 ...

  return { chunkCount: chunks.length };
}
```

## 6. 文档解析（后续做，先知道）

把 PDF/DOCX 变成纯文本，遵守项目 P0 安全边界（单文件 ≤50MiB；拒加密/宏/可执行/压缩包；限页数/耗时）。
