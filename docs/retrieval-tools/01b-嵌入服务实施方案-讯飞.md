# 01b · 嵌入服务实施方案（讯飞星火）

> 本方案基于 [`01-嵌入服务.md`](./01-嵌入服务.md) 的接口设计，把"后端实现"具体落到**讯飞星火的 Embedding + Rerank 服务**。
> 目标：写成一套调用工具，后续同事接上智能体（agentic 或单独调用）就能直接用。

---

## 0. 关于 reranker：要不要用？

**要，本期和 embedding 一起做。** 它和 embedding 是检索链路里两个不同环节：

```
用户问题 → ① embedding(问题向量化)
         → ② 召回(向量检索粗筛出 Top 20)
         → ③ reranker(精排，从 20 里挑最相关的 Top 5)  ← 讯飞免费给了，用上
```

- **②召回**快但糙，会把"字面像、意思不对"的段落也捞出来。
- **③reranker**慢但准（交叉模型，query 和文档一起算相关性），负责把真正相关的顶到前面。

**为什么本期就做**：文档索引在先（一次性批量），检索时 reranker 处理的只是召回出的几十段（量小），免费额度完全扛得住。所以不再后置，和 embedding 一起完成。

---

## 1. 讯飞有两套接口，我们用哪套（关键决策）

经核实讯飞官方文档，讯飞有**两套**接口：

| 接口套件 | 鉴权 | Embedding 格式 | 复杂度 |
| --- | --- | --- | --- |
| **A. 老接口（Embeddingp/q）** | appid + APIKey + APISecret **签名 URL** | base64 编码的 float32 字节流，要自己解码 | 高（4 个坑） |
| **B. MaaS API（推荐 ⭐）** | `Authorization: Bearer <APIPassword>` | **标准 OpenAI 格式**，直接拿 JSON 向量 | **低**（和别家几乎一样） |

> **我们用 B（MaaS API）**。理由：① 标准 OpenAI 兼容格式，和 [`01-嵌入服务.md`](./01-嵌入服务.md) 里设计的 `provider-api.ts` 几乎通用；② Embedding 和 Rerank 走同一套鉴权、同一个根地址，统一；③ 不用写签名、不用 base64 解码，代码量少一半。
>
> 老接口 A 仅作为"存量用户/特殊需求"的备选，不在本期实现。

### 1.1 MaaS API 总览（Embedding + Rerank 共用）

> ✅ **已从控制台确认**：Embedding 和 Reranker 均为 **Qwen3-8B 系列**，已开通运行中。
> ✅ **模型 ID（控制台实测）**：`xop3qwen8bembedding`（Embedding）、`xop3qwen8breranker`（Reranker）。

| 项 | Embedding | Rerank |
| --- | --- | --- |
| 根地址 | `https://maas-api.cn-huabei-1.xf-yun.com` | 同左 |
| 路径 | `/v1/embeddings` | `/v1/rerank` |
| 鉴权 | `Authorization: Bearer <APIPassword>` | 同左 |
| 模型 ID | `xop3qwen8bembedding` | `xop3qwen8breranker` |
| 请求体 | `{ model, input }` | `{ model, query, documents }` |
| 响应 | OpenAI 格式（`data[].embedding`） | `{ results: [{index, relevance_score}] }` |

> ⚠️ **地址版本**：账号 2026-01-10 后注册用 `/v2`，之前用 `/v1`。**以控制台详情页地址为准**；代码做成可配置（改一处文档即可）。

## 2. 接口详情（MaaS API，已从官方文档核实）

### 2.1 Embedding 请求/响应

请求：
```json
POST https://maas-api.cn-huabei-1.xf-yun.com/v1/embeddings
Authorization: Bearer <APIPassword>
Content-Type: application/json

{
  "model": "xop3qwen0b6embedding",
  "input": ["文本1", "文本2"]
}
```
响应（标准 OpenAI 格式）：
```json
{
  "data": [
    { "embedding": [0.12, 0.85, ...], "index": 0 },
    { "embedding": [0.33, 0.71, ...], "index": 1 }
  ],
  "usage": { ... }
}
```
> 向量直接是 JSON 数字，**不用 base64 解码**。维度以实际返回为准（需你联调时确认，用来对齐建表的向量列维度）。

### 2.2 Rerank 请求/响应

请求：
```json
POST https://maas-api.cn-huabei-1.xf-yun.com/v1/rerank
Authorization: Bearer <APIPassword>
Content-Type: application/json

{
  "model": "xop3qwen0b6reranker",
  "query": "用户的查询语句",
  "documents": ["候选文档1", "候选文档2", "候选文档3"]
}
```
响应：
```json
{
  "results": [
    { "index": 2, "relevance_score": 0.95 },
    { "index": 0, "relevance_score": 0.41 },
    { "index": 1, "relevance_score": 0.12 }
  ],
  "usage": { ... }
}
```
> ⚠️ **官方明确：返回的 `results` 数组默认不按分数排序，必须自己按 `relevance_score` 排序后再用。**
> `index` 是对应原 `documents` 数组的下标，用它回溯原文。

### 2.3 对上层的固定接口（不受讯飞格式影响）

无论用哪家后端，**对上层暴露的接口是固定的**。Embedding 用 [`01-嵌入服务.md`](./01-嵌入服务.md) 的 `Embedder` 接口；Reranker 用下面的接口：

```ts
// src/server/retrieval/reranker.ts
/** rerank 输入 */
export interface RerankInput {
  query: string;            // 用户问题
  documents: string[];      // 召回出的候选文档片段（粗筛后的几十段）
  topN?: number;            // 返回前 N 条，默认全部返回
}

/** 单条 rerank 结果 */
export interface RerankItem {
  index: number;            // 在原 documents 数组里的下标（便于回溯原文）
  score: number;            // 相关性分数（越高越相关）
  text: string;             // 文档片段原文
}

/** Reranker 接口：所有实现（讯飞/别家）都满足这个形状 */
export interface Reranker {
  rerank(input: RerankInput): Promise<RerankItem[]>;
}
```

> 这个接口设计成"输入一组文档，输出按相关性排序的结果"。**讯飞 rerank 的实际请求/响应格式变化，都封装在 `xfyun-rerank.ts` 内部**，不影响上层 `hybrid_search` 怎么用它——这和 embedder 的思路一致（接口固定，实现可换）。

## 3. 要写的文件（清单）

因为用了 MaaS API（标准格式），**不需要**签名鉴权文件、不需要 base64 解码，文件比原计划少：

```
src/server/retrieval/
  ├─ embedder.ts                    接口定义（已在 01 设计好，照搬）
  ├─ embedders/
  │    └─ xfyun-maas.ts             【新】讯飞 MaaS 实现（Embedding + Rerank 都在这，OpenAI 兼容格式）
  ├─ embedder-instance.ts           统一出口（实例化讯飞 embedding）
  ├─ reranker.ts                    【新】Reranker 接口定义（RerankInput/RerankItem/Reranker）
  └─ reranker-instance.ts           【新】统一出口（实例化讯飞 reranker）
```

> 这些文件都在 `src/server/`（lib 层），**不碰 eve、不碰同事的代码**。
> 因为 Embedding 和 Rerank 走同一套 MaaS 鉴权，实现可以合并到 `xfyun-maas.ts` 一个文件里（共用 fetch + Bearer 鉴权逻辑）。

## 4. 实施步骤（认可后我按此执行）

### 步骤 1：写讯飞 MaaS 实现 `xfyun-maas.ts`
- 共用的 HTTP 调用（Bearer 鉴权、超时、错误处理）。

- `embedder-instance.ts`：实例化讯飞 embedding。
- `reranker-instance.ts`：实例化讯飞 reranker。
- 都从环境变量读 `XFYUN_API_PASSWORD`（MaaS 只需 APIPassword）。

### 步骤 4：跑通验证（临时脚本）
- `embedder.embed("怎么报销")` → 返回向量 ✅
- `embedder.embedBatch(["文本1","文本2"])` → 批量向量 ✅
- `reranker.rerank({ query, documents })` → 返回按分数排序的结果 ✅

| 信息 | 用途 | 放哪 |
