# 依赖兼容例外

本文件记录超出上游声明兼容范围的依赖覆盖。每项例外必须包含原因、约束、验证方式和明确的移除条件，不得作为无期限依赖策略。

## Next.js 与 Sharp

- 状态：临时例外
- 直接依赖：Next.js `16.2.12`
- 上游声明范围：Sharp `^0.34.5`
- 实际覆盖版本：Sharp `0.35.3`
- 原因：Sharp `<0.35.0` 受 `GHSA-f88m-g3jw-g9cj` 影响，继续安装上游声明范围内的版本会保留生产依赖高危公告。

### 使用约束

- 当前应用不使用 `next/image` 或 Next.js 图片优化端点。
- `next.config.ts` 必须保持 `images.unoptimized: true`，不得在没有兼容性验收的情况下启用图片优化。
- 文件和图片处理能力不得依赖该 Sharp 覆盖；P6 必须选择并验证自己的受限解析链路。

### 当前验证

- `npm run build` 验证 Next.js 与 eve 生产构建。
- Sharp 直接调用验证 1x1 PNG 编码能力。
- `npm audit --omit=dev --audit-level=high` 验证生产依赖不存在已知高危公告。

上述验证不代表 Next.js 图片优化器与 Sharp `0.35.x` 完全兼容，因此该路径保持关闭。

### 移除条件

满足以下任一条件时必须移除 `package.json` 中的 Sharp 覆盖并更新本文件：

1. 稳定版 Next.js 正式声明支持不受该公告影响的 Sharp 版本。
2. 项目确认永久不使用 Next.js 图片优化，并能从安装产物中安全移除 Sharp。

如果未来必须在上游正式支持前启用图片优化，应先增加覆盖真实 `/_next/image` 请求的集成测试，并重新确认该例外。

## 百工维护的 eve 交互式恢复版本

- 状态：临时例外
- 官方基线：`eve@0.27.11`，提交 `eece47d267fe849037febd9c4b677e4168f3d7e7`
- 实际版本：`eve@0.27.12-baigong.0`
- 签名标签：`eve-v0.27.12-baigong.0`
- 下载地址：`https://github.com/Procyon-Nan/eve/releases/download/eve-v0.27.12-baigong.0/eve-0.27.12-baigong.0.tgz`
- SHA-256：`aab80058e3437829d851cd2b4d5fbf4f14998f74d52c2901b6466f4d22e2d115`
- 原因：官方 `eve@0.27.11` 在交互式模型调用错误耗尽后终止整个会话，无法满足 P3 修复模型配置后继续原会话的要求。

### 使用约束

- `package.json` 使用精确 HTTPS tarball URL，不使用 semver 范围或可变分支。
- `package-lock.json` 必须保存同一下载地址和 integrity；`npm ci` 不得依赖本地 eve 源码目录。
- Git tag、GitHub Release 附件和校验值保持不可变；内容变化时发布新的 `baigong` 版本。
- 该版本只修改交互式模型错误恢复语义，不作为官方 eve 发行版对外声明。
- P3 当前未声明 Connection 或需要 Vercel Connect 的 Channel，因此移除未使用的 `@vercel/connect` 直接依赖。其 `eve >=0.13.7` peer range 不接受预发布版本，会使 `npm ls eve` 将已验证的下游包标记为无效。

### 当前验证

- eve 专项测试覆盖认证失败、模型不存在、普通 `4xx`、`429`、超时、`5xx`、取消、任务模式和原 continuation 恢复。
- eve 类型检查、文档检查、代码不变量检查和构建通过。
- Release 附件已在无 GitHub 凭据的环境中下载，并通过发布的 SHA-256 校验。
- tarball 已在独立临时目录安装，验证 `eve`、`eve/client`、`eve/channels/eve` 导入和 `eve` CLI。
- baigong-agent 中 `npm ls eve` 必须得到单一的 `eve@0.27.12-baigong.0`，且不得出现 `file:` 或本机源码路径。

### 移除条件

满足以下条件后移除该例外并更新锁文件：

1. 官方 eve 精确版本包含相同交互式恢复语义和自动化测试。
2. 该官方版本通过 P3 数据库、HTTP、真实模型和浏览器验收。

P5 或后续阶段引入 Connection、Slack 等依赖 Vercel Connect 的能力时，应重新选择与当前 eve 版本兼容的 `@vercel/connect` 版本并完成对应集成测试，不能仅为保留未使用依赖而忽略 peer dependency 失败。
