# P4：会话与审计持久化

> 状态：决策已定稿，待实施  
> 定稿日期：2026-08-03  
> 前置阶段：P0、P1、P2、P3 已完成

## 1. 目标

P4 在 P3 已交付的安全对话主链路上增加应用权威历史和执行索引，使本地用户、嵌入用户和管理员在页面刷新、会话切换或进程重启后仍能恢复会话状态，同时保持 eve 原始事件、普通用户安全投影和管理员直连原始流三条边界不混用。

P4 完成后，P2 至 P4 组成首个可验收版本。该版本至少具备：

- 顶层主会话列表、重命名、归档和恢复。
- 权威消息历史、流式草稿恢复和单调事件游标。
- 每轮及每会话 Token 汇总和上下文窗口展示。
- Tool、终端和 Subagent 执行审计索引。
- 主会话与 Subagent 子会话的安全父子关系。
- 管理员独立“会话审计”页面。
- 本地用户、嵌入用户、管理员和跨用户访问隔离。

## 2. 既有基线

### 2.1 直接复用的 P3 能力

- `conversations` 保存应用会话、eve 会话映射、加密 continuation token、控制状态和最后 eve 游标。
- `conversation_turns` 保存请求幂等键、锁定模型版本、eve Turn 映射和单轮状态。
- `monitorEveEvents` 在浏览器未连接时继续消费 eve 持久事件。
- 普通用户通过 BFF 接收允许列表投影后的 NDJSON 事件。
- 管理员通过会话绑定的短期令牌直连 eve 原始流。
- 本地用户和嵌入用户已经归一为 `AuthenticatedPrincipal`，但身份来源永久隔离。
- 模型配置版本已经保存 `contextWindowTokens`，每个 Turn 已锁定实际配置版本。

### 2.2 当前缺口

- 浏览器消息仅存在于 React 内存，切换页面或刷新后丢失。
- 没有顶层会话列表、归档、恢复或标题管理。
- PostgreSQL 尚未保存用户安全消息快照和轻量状态事件。
- 尚未保存逐步骤 Token、Tool/终端审计索引或 Subagent 父子映射。
- 管理员只能查看已知会话的实时原始流，没有全租户会话审计入口。

### 2.3 eve 实际事件能力

固定依赖 `eve@0.27.12-baigong.0` 已提供 P4 所需事件：

- `message.received`：用户或委派输入。
- `message.appended`、`message.completed`：助手流式文本和完成文本。
- `step.completed`：输入、输出、缓存 Token 和可选费用。
- `actions.requested`、`action.result`：Tool、Skill 和 Subagent 调用生命周期。
- `subagent.called`：子会话 ID、调用 ID、名称和父 Turn。
- 子会话 `session.started.invocation`：父会话、父 Turn、父调用和 Subagent 名称。
- `input.requested`、`authorization.required`：从子会话代理回根会话的交互请求。
- `session.waiting`：可继续会话的 continuation token。

eve `SessionState` 只是继续令牌和远端流游标，不是聊天历史。P4 必须持久化应用自己的安全消息和索引。

## 3. 范围边界

### 3.1 P4 范围

- 统一主会话和 Subagent 子会话的数据模型。
- 用户自己的顶层会话列表、标题、重命名、归档和恢复。
- 管理员独立会话审计列表和只读详情。
- 安全消息、轻量状态事件、流式草稿和 eve 游标持久化。
- Token、上下文窗口、可选费用和 Subagent 用量归集。
- Tool、终端和其他运行动作的审计索引。
- Subagent 父子关系、用户安全视图和只读访问控制。
- 启动校正、打开会话时的有限追赶和重复事件幂等。
- 独立 P4 数据库测试和 HTTP 验收。

### 3.2 P4 不做

- 不启用 Tool、终端、Skill 或 Subagent 运行能力。
- 不实现真实 Tool、终端或 Subagent 的浏览器验收；随 P5 能力启用后验收。
- 不实现会话删除、消息编辑、历史改写或管理员代用户继续。
- 不实现全文搜索、标签、文件夹、批量操作或系统级保留策略。
- 不实现全局审计记录修改、删除和清理管理页面；P7/P10 再完成。
- 不复制 eve 完整原始事件、推理内容、完整 Tool 参数或完整命令输出到 PostgreSQL。
- 不引入 Redis、S3、SMTP、消息队列、多副本协调或特定宿主适配。

## 4. 会话模型

### 4.1 统一会话类型

现有 `conversations` 表继续作为唯一应用会话表，增加：

| 字段 | 说明 |
| --- | --- |
| `kind` | `MAIN` 或 `SUBAGENT` |
| `title` | 顶层显示标题；纯文本保存 |
| `archived_at` | 顶层会话归档时间，未归档为 `NULL` |
| `parent_conversation_id` | 子会话所属父会话 |
| `parent_turn_id` | 产生委派的父 Turn |
| `delegation_call_id` | eve 父调用 ID |
| `subagent_name` | 子会话的可展示 Subagent 名称 |
| `link_status` | 父事件与子事件关系校验状态 |
| `parent_called_cursor` | 父流观察到 `subagent.called` 的游标 |
| `child_started_cursor` | 子流观察到 `session.started` 的游标 |

数据库约束必须保证：

- `MAIN` 的父关联字段全部为空。
- `SUBAGENT` 的父会话、父 Turn、调用 ID和名称全部存在。
- 子会话与父会话具有相同租户、所有者和身份来源。
- 同一父会话内的 `delegation_call_id` 唯一。
- 顶层列表只查询 `MAIN`。
- Subagent 不计入用户 50 条顶层未归档会话额度。

### 4.2 会话标题

- 新主会话标题默认取第一条用户消息。
- 压缩连续空白并去除 Markdown 控制表现后，截取前 60 个 Unicode 字符。
- 标题只按纯文本展示，不渲染 Markdown 或 HTML。
- 所有者可以重命名自己的主会话。
- 管理员不能重命名他人会话。
- Subagent 标题由 Subagent 名称和委派任务摘要形成，不能独立重命名。

### 4.3 会话数量与归档

- 每个用户最多拥有 50 条未归档的 `MAIN` 会话。
- 达到上限时拒绝新建，并提示用户先归档一条会话。
- 已归档主会话不占额度，Subagent 子会话不占额度。
- 系统不自动归档。
- `STARTING`、`RUNNING` 和 `CANCELLING` 会话不能归档。
- `WAITING`、`TERMINAL_FAILED` 和 `TERMINAL_COMPLETED` 会话可以归档。
- 恢复归档会话时重新检查 50 条限制。
- 首版不提供会话删除。

## 5. 消息、重试和状态历史

### 5.1 消息表

新增 `conversation_messages`，至少包含：

- `id`、`tenant_id`、`conversation_id`、`turn_id`。
- `role`：`USER`、`ASSISTANT`、`DELEGATION`。
- 稳定公开 `block_id` 或输入消息标识。
- 消息正文和完成状态。
- 首次及最后对应的 eve 游标。
- 创建、更新时间。

消息表只保存普通用户允许看到的文本和后续安全文件引用，不保存原始事件、推理、Tool 参数、终端内容、系统提示词或 eve 句柄。

### 5.2 用户消息与重试

- 用户消息通过身份、格式、模型可用性、数量和并发校验，并成功预留 Turn 后立即落库。
- 预留 Turn 之前被拒绝的请求不写历史。
- 模型失败或用户取消后，已经接受的用户消息仍保留。
- 失败回复重试时创建新的 Turn 和 `requestId`，但复用原用户消息。
- `conversation_turns` 增加输入消息关联和 `retry_of_turn_id`。
- 用户主动再次发送相同文本始终是新消息，不进行文本去重。

### 5.3 助手草稿

- `message.appended` 更新同一个未完成助手消息的当前文本和最新游标。
- 不为每个文本增量保存完整 JSON 事件或重复文本快照。
- `message.completed` 保存最终正文并标记完成。
- 一个 Turn 中多个已完成助手文本块按 eve 顺序分别保存。
- 用户主动取消时保留已经产生的半成品，并标记“已停止生成”。
- 可恢复模型失败或结构性会话失败时不向用户展示当前未完成草稿，但保留已经完成的消息。

### 5.4 轻量安全事件

新增轻量、追加式状态事件表，保存：

- 会话与 Turn 状态变化。
- 公开失败或取消结果。
- 消息完成边界。
- 对应 eve 原始游标和事件时间。

不持久化心跳，不保存完整原始事件。历史页面以消息和当前状态快照为主，不通过重放全部事件重新构建正文。

## 6. 游标、事务与恢复

### 6.1 单一持久化处理器

P4 将 P3 生命周期处理扩展为统一事件持久化处理器。后台监控、用户流、启动校正和历史追赶全部调用同一实现。

每个 eve 事件在一个数据库事务内完成：

1. 以 `(conversation_id, eve_cursor)` 检查幂等。
2. 更新会话和 Turn 生命周期。
3. 更新消息快照或轻量状态事件。
4. 更新 Token、动作审计或 Subagent 关联。
5. 推进最后已持久化 eve 游标。

游标不能先于消息和状态提交。

### 6.2 普通用户流

- 原始事件先持久化，再执行安全投影并返回浏览器。
- 数据库写入失败时关闭普通用户流，不伪造失败或终止状态。
- 客户端保持重连状态，从最后已持久化游标继续。
- 心跳不推进 durable 游标。

### 6.3 启动与读取校正

- 启动时校正 `STARTING`、`RUNNING` 和 `CANCELLING` 会话。
- 打开会话历史时，从 PostgreSQL 游标到 eve 当前尾部执行一次 `follow: false` 的有限追赶。
- eve 暂时不可用时仍允许读取已保存历史，但标记实时状态暂不可确认，并拒绝冲突写操作。
- 管理员原始流继续直接读取 eve，不改为 BFF 转发。

## 7. Token 与上下文

### 7.1 逐步骤记录

新增逐步骤 Token 表，以会话、Turn、eve Turn 和 `stepIndex` 唯一，保存：

- `input_tokens`。
- `output_tokens`。
- `cache_read_tokens`。
- `cache_write_tokens`。
- 可选 `cost_usd`。
- 事件游标和时间。

提供商未返回的字段保存为 `NULL`，不按零处理，也不自行估算。

### 7.2 汇总口径

- Turn 汇总其所有成功完成的模型步骤。
- 会话分别展示主 Agent 直接用量、Subagent 用量和合计。
- Subagent 用量在父会话中只归集一次，不能因子会话独立记录而重复计算。
- 当前上下文使用量取主 Agent 最近一次模型步骤的 `inputTokens`。
- 最大上下文窗口读取该 Turn 锁定的 `model_config_versions.context_window_tokens`。
- 历史 Turn 始终使用当时锁定的模型版本，不被后来配置覆盖。
- `costUsd` 仅在实际返回时保存并供管理员查看。

## 8. Tool、终端与运行动作审计

新增运行动作审计索引，至少保存：

- 租户、会话、Turn 和模型步骤。
- eve `callId`、动作类型、Tool 或 Subagent 名称。
- 请求事件游标和结果事件游标。
- 开始、结束时间。
- `completed`、`failed`、`rejected` 或 `pending` 状态。
- 脱敏错误码和完整详情是否存在。

PostgreSQL 不保存完整 Tool 参数、结果、终端命令输出或推理内容。管理员需要完整详情时，根据索引游标申请短期管理员流令牌，并由浏览器直接读取 eve 持久原始流。

如果 eve 原始历史暂时不可用，界面显示调用名称、状态、时间、游标和“完整详情暂时不可用”，不猜测内容。

P5 的终端操作复用该索引并增加动作分类，不建立第二套审计模型。

## 9. Subagent 安全会话

### 9.1 父子关系

- 父流 `subagent.called` 创建或补全 `SUBAGENT` 会话。
- 子流 `session.started.invocation` 反向验证父会话、父 Turn、父调用和名称。
- 两侧一致时幂等合并并将 `link_status` 标记为已验证。
- 不一致时失败关闭，禁止用户进入或继续，并记录安全审计。
- 用户只能通过已验证父关系进入子会话。

### 9.2 用户可见内容

用户可以看到：

- Subagent 名称。
- 标记为“主 Agent 委派”的安全委派任务文本。
- Subagent 的安全助手消息和通用状态。
- 用户后来直接发送的消息。
- 安全 Token 摘要。

用户不能看到：

- Tool、终端、推理、系统提示词和原始错误。
- eve 子会话 ID、continuation token、调用 ID和工作流 ID。
- 未知或未投影的原始事件。

### 9.3 交互语义

- Subagent 执行原始委派期间，子会话安全内容可读，但不能插入任意消息。
- `input.requested` 和 `authorization.required` 由 eve 代理回根会话处理。
- 根会话只投影能够匹配当前主会话 Turn 或已验证子会话 Turn 的交互请求；未知 Turn 或尚未验证的子会话请求直接丢弃。
- 主会话显示“来自 Subagent 的问题或授权请求”；父 Agent 等待，处理结果由 eve 路由回子会话。
- 子会话页面只显示等待状态和返回主会话入口。
- Subagent 以 eve `task` 模式执行；原始委派完成时发出 `session.completed`，不转换为普通可继续对话。
- 原始委派完成后子会话仍为只读，用户不能再向该子会话发送新消息。
- 管理员可以查看或取消他人正在执行的子会话，但不能代替所有者发送消息。

### 9.4 阶段边界

P4 完成数据、接口、投影、授权和模拟事件测试，但继续禁用实际 Subagent 能力。P5 启用主 Agent 单层 Subagent 后再执行真实浏览器验收；子 Agent 仍不能继续产生 Subagent。

## 10. 列表、分页与历史快照

### 10.1 用户列表

- 每页 10 条 `MAIN` 会话。
- 使用 `(updated_at, id)` 游标分页，不使用 offset。
- 默认按最近活动时间倒序。
- 默认只显示未归档会话，可切换已归档视图。
- 登录后默认打开最近活动的未归档会话；没有会话时显示新对话。

### 10.2 历史读取

- 消息按时间正序显示。
- 接口从最新历史开始分页，向上滚动加载更早消息。
- 打开会话时在一个权威响应中返回：会话状态、活动 Turn、当前页消息、最新持久游标、Token 汇总和是否还有更早历史。
- 客户端完成快照加载后，再从下一游标连接实时流。
- 会话切换只终止旧页面流，不取消正在执行的 Turn。

### 10.3 用户消息位置轨道

- 聊天消息区域左侧显示一条细竖向导航轨道。
- 每条用户消息对应一个位置标记。
- 点击标记加载必要历史并滚动到对应用户消息。
- 当前视口附近的标记高亮，悬停显示摘要和时间。
- 服务端提供轻量用户消息节点索引；索引可分页加载，但不要求先加载完整消息正文。
- Subagent 委派不占用位置标记，仍通过时间线中的 Subagent 卡片进入。
- 移动端改用可展开的位置列表。

## 11. 管理员会话审计

### 11.1 独立页面

新增与模型管理、用户管理和嵌入接入并列的管理入口：

- `/admin/conversations`：会话审计列表。
- `/admin/conversations/[conversationId]`：只读会话审计详情。

管理员自己的聊天侧栏只显示自己的会话，不混入其他用户会话。

### 11.2 列表与权限

- 列出本租户所有本地和嵌入用户的 `MAIN` 会话。
- 支持按用户、身份来源、状态和归档状态筛选。
- 每页 10 条。
- 显示所有者、身份来源、标题、状态、最后活动时间和归档状态。

管理员查看他人会话时：

- 可以查看安全历史、Token、Subagent 树和原始执行详情。
- 可以取消正在运行的 Turn。
- 可以归档会话。
- 不能发送、重试、重命名、恢复为自己所有或修改历史。

查看详情、进入子会话、签发原始流令牌、取消和归档他人会话均记录安全审计。

### 11.3 全局审计边界

P4 不新增全局安全审计管理页面，不开放审计记录修改、删除和批量清理接口。P2/P3 已有安全审计继续写入。P7 完成管理体验，P10 完成系统级保留策略和清理验收。

## 12. 嵌入历史

- 嵌入用户复用同一会话、历史和归档服务。
- 只允许访问同一嵌入客户端、同一稳定外部用户映射创建的会话。
- 同一外部用户以后通过同一客户端取得新票据时可以恢复历史。
- 不同嵌入客户端即使外部用户标识相同，也永久隔离。
- 嵌入页面使用紧凑会话抽屉，支持选择、重命名和归档。
- 嵌入用户独立计算 50 条未归档主会话上限。
- P4 完成现有 `/embed` 的基础历史能力；正式组件、示例和完整浏览器验收仍留到 P9。

## 13. API 设计

建议应用接口：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/conversations` | 查询所有者的顶层会话列表 |
| `POST /api/conversations` | 创建主会话和首条消息 |
| `GET /api/conversations/:id` | 获取权威会话快照 |
| `PATCH /api/conversations/:id` | 重命名所有者的主会话 |
| `POST /api/conversations/:id/archive` | 归档主会话 |
| `POST /api/conversations/:id/restore` | 恢复主会话 |
| `GET /api/conversations/:id/messages` | 分页读取安全消息历史 |
| `GET /api/conversations/:id/nodes` | 读取用户消息位置索引 |
| `POST /api/conversations/:id/messages` | 继续等待中的主会话；Subagent 子会话始终只读 |
| `GET /api/conversations/:id/events` | 从游标读取实时安全事件 |
| `GET /api/admin/conversations` | 管理员会话审计列表 |
| `GET /api/admin/conversations/:id` | 管理员只读审计详情 |
| `GET /api/admin/conversations/:id/execution-index` | Token、动作和子会话索引 |
| `POST /api/admin/conversations/:id/stream-token` | 签发指定主或子会话原始流令牌 |

所有接口使用严格 Zod Schema。普通响应不得包含 eve session ID、continuation token、内部调用 ID、模型凭据、完整 Tool 数据或原始事件。

### 16.2 独立测试数据库

当前角色 `baigong_agent_app` 没有创建数据库权限。实施数据库验收前，由具有 PostgreSQL 管理权限的用户执行：

```bash
sudo -u postgres psql -v ON_ERROR_STOP=1 <<'SQL'
SELECT 'CREATE DATABASE baigong_agent_p4_test OWNER baigong_agent_app'
WHERE NOT EXISTS (
  SELECT 1 FROM pg_database WHERE datname = 'baigong_agent_p4_test'
)\gexec
GRANT ALL PRIVILEGES ON DATABASE baigong_agent_p4_test TO baigong_agent_app;
SQL
```

随后在本地 `.env` 增加独立连接：

```dotenv
P4_TEST_DATABASE_URL=postgresql://baigong_agent_app:<现有应用角色密码>@127.0.0.1:5432/baigong_agent_p4_test
```

不得把实际密码提交到 Git，也不得让 `P4_TEST_DATABASE_URL` 与 `DATABASE_URL` 指向同一数据库。

## 17. 测试策略

### 17.1 隔离要求

- 未配置 `P4_TEST_DATABASE_URL` 时，P4 数据库和 HTTP 测试立即拒绝运行。
- 与应用数据库相同时立即拒绝运行。
- 测试库名称必须符合独立测试库约束。
- 每次运行生成随机租户、用户、会话、子会话、消息和事件标识。
- 成功或失败后都清理本次数据。
- 自动化使用假的 eve 事件流，不访问真实模型或真实凭据。

- 会话列表、10 条游标分页和 50 条未归档限制。
- 自动标题、重命名、归档和恢复。
- 历史快照、旧消息分页和用户消息位置节点。

- 事件重复、游标跳跃、写入失败和有限追赶。

### 17.3 人工验收边界
