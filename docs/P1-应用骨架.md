# P1：应用骨架

> 文件名：`docs/P1-应用骨架.md`  
> 状态：已完成

## 1. 阶段范围

P1 建立可运行的 Next.js、eve 与 PostgreSQL/Drizzle 基础结构，不实现 P2 身份认证、P3 对话主链路或 P7 管理配置业务。所有实现遵守 [`docs/P0-技术与安全边界.md`](./P0-技术与安全边界.md)。

## 2. 已完成内容

### 2.1 Next.js 与 eve 同源应用

- `next.config.ts` 使用 `withEve()` 挂载根目录 `agent/`，开发和生产均由 Next.js 同源代理 eve 路由。
- `package.json` 的 `dev`、`build` 和 `start` 已切换到 Next.js 应用生命周期；生产构建先执行 `eve build`，再执行 `next build`。
- `agent/channels/eve.ts` 仅保留开发环境有效的 `localDev()`。生产环境在 BFF 服务令牌验证器实现前保持失败关闭。
- `agent/unconfigured-model.ts` 提供不会访问任何外部提供商的失败关闭模型。未通过管理配置分配模型时，对话不会回退到代码中的生产模型。

### 2.2 基础页面与错误处理

- `app/page.tsx` 和 `app/components/` 提供响应式系统状态工作台，显示应用服务、项目数据目录、PostgreSQL 和模型连接状态。组件样式使用 CSS Modules 隔离，`app/globals.css` 仅保留设计令牌和全局基线。
- 未配置模型时应用运行于仅管理模式，对话入口保持关闭。
- `app/components/navigation-model.ts` 集中声明路由、图标和模式可见性，导航组件依当前路径计算激活状态。该模型只控制展示，不替代 P2 服务端授权。
- `app/error.tsx`、`app/global-error.tsx` 和 `app/not-found.tsx` 处理路由、全局与 404 页面错误。
- `src/server/errors.ts` 提供统一的应用错误、HTTP 状态和前端安全错误投影，未知异常不返回内部详情。
- `app/api/health/route.ts` 提供不包含凭据和内部路径的基础设施健康状态。

### 2.3 环境与项目数据目录

- `.env.example` 仅包含 `DATABASE_URL` 和 `BAIGONG_DATA_DIR` 等基础设施配置，不包含模型提供商凭据。
- `src/server/config/environment.ts` 使用 Zod 延迟校验服务端配置，构建过程不依赖运行时数据库。
- `src/server/config/data-directory.ts` 创建持久化项目数据目录，并以独占创建方式生成 32 字节凭据加密主密钥和 JWT 签名密钥。
- `instrumentation.ts` 在 Node.js 服务启动时调用 `src/server/bootstrap.ts` 执行一次性初始化；运行状态检查仅读验证目录和密钥，不创建或修改持久化数据。
- `.data/`、`.env*` 和构建产物均已加入 `.gitignore`；`.env.example` 明确允许提交。
- Unix 文件系统上目录和密钥分别请求 `0700` 与 `0600`。WSL 开发可使用项目根目录下的 `.data`；Windows 挂载的最终权限由 Windows ACL 决定，作为已知开发环境例外。
- 纯 Linux 生产环境也可使用项目根目录下的 `.data`，但 `BAIGONG_DATA_DIR` 必须指向 Linux 原生文件系统上的绝对路径，并满足持久化、非 Web 公开、不进入 Git、应用用户独占及 `0700`/`0600` 权限要求；容器部署时必须挂载为持久卷。

### 2.4 PostgreSQL 与 Drizzle

- `drizzle.config.ts` 定义 PostgreSQL 方言、Schema 路径和迁移目录。
- `src/server/db/client.ts` 提供单实例共享连接池、Drizzle 客户端、连接探测和显式关闭能力。
- `src/server/db/schema/tenants.ts` 建立租户基础表；后续用户、会话、文件、记忆和凭据表必须引用租户边界。
- `drizzle/0000_silky_black_crow.sql` 是首个版本化迁移，创建租户表、唯一索引和 slug 约束。
- `scripts/migrate.ts` 使用 Drizzle migrator 执行迁移；`node --conditions=react-server --import tsx` 既保持 `server-only` 边界，也避免 WSL 环境下 `tsx` CLI 的跨文件系统 IPC 问题。

### 2.5 依赖与安全基线

- Web 使用 Next.js `16.2.12`、React `19.2.8`；数据库使用 Drizzle ORM `0.45.2` 和 `pg` `8.22.0`。
- Next.js 的传递依赖覆盖为 PostCSS `8.5.24` 和 Sharp `0.35.3`，规避已公开的旧版本高危公告。
- Sharp 覆盖的兼容范围、验证措施和移除条件记录在 [`docs/依赖兼容例外.md`](./依赖兼容例外.md)。当前未使用 Next 图片优化器，并通过 `images.unoptimized` 明确关闭该路径。
- Auth.js 未在 P1 提前接入。P2 必须依据届时安装版本的实际文档和适配器接口实现数据库会话。
- 数据目录、环境配置、数据库、应用初始化和就绪检查模块均引入 `server-only`，防止后续界面代码误将敏感实现纳入客户端依赖图。
- 用户提供的模型端点、模型名称和 API Key 未写入源码、环境文件、日志或测试。提供商配置仍由后续管理页面加密写入。

## 3. 验收结果

以下检查均已于 2026-07-29 在 WSL 中通过：

- `npm run build`
- `npm run typecheck`
- `npm test`：5 个测试文件、13 项测试通过
- `npm run db:check`
- `npm audit --omit=dev --audit-level=high`：生产依赖 0 个漏洞
- Next.js 首页返回 `200`，系统状态页面可渲染
- 未配置 `DATABASE_URL` 时 `/api/health` 返回 `503`，明确标记数据库待配置和模型未配置
- 同源 `/eve/v1/health` 返回 `200`
- 自定义 404 页面返回 `404`
- 在隔离的临时 PostgreSQL 16 实例中成功执行 `npm run db:migrate`，确认创建迁移记录表、租户表和约束；测试后实例及数据目录已删除

## 5. 下一阶段边界

P2 在本骨架上实现登录和权限。P2 开始前必须完整阅读实际安装版本的 Auth.js 与 Drizzle Adapter 文档，并确认用户名或邮箱加密码与数据库会话的兼容实现方式。P2 不得开放匿名管理访问，也不得以浏览器可控字段作为租户、角色或用户身份依据。
